# 指导老师工号确认须知

## 1. 为什么需要确认

科研项目管理平台需要为每一位指导老师设置一个长期稳定、不会重复的人员编号，用于：

- 区分同名老师。
- 防止同一位老师被重复导入人员库。
- 查询老师指导过哪些项目。
- 关联老师的单位、联系方式、职务或职称。
- 在老师姓名、单位或联系方式发生变化后，仍能识别为同一个人。

当前标准导入模板暂时使用 `teacher_no`（工号）作为指导老师的唯一编号。

第一版平台不向指导老师开放登录账号，因此工号目前只用于后台人员识别和数据关联，不代表为老师创建网站账号。

## 2. 需要向学校确认的问题

请向掌握教师信息的老师、学院或相关管理部门确认：

1. 校内指导老师是否都有唯一且长期不变的正式工号？
2. 兼职教师、退休返聘教师、校外指导老师是否也有学校工号？
3. 历年项目资料中能否取得指导老师工号，还是只有姓名和单位？
4. 工号应当向哪个部门或系统获取，是否可以批量提供？
5. 工号是否允许用于本平台的内部数据管理？
6. 工号是否属于需要限制查看的内部信息？

## 3. 建议采用的处理方案

### 情况 A：所有指导老师都有工号

- 使用学校正式工号作为 `teacher_no`。
- 同一个老师在所有项目中必须使用同一个工号。
- 不根据姓名、电话或邮箱另外生成编号。

这是最简单、最稳定的方案。

### 情况 B：校内老师有工号，校外老师没有

- 校内老师使用学校正式工号。
- 校外老师由系统生成独立编号，例如 `EXT-2026-0001`。
- 人员资料中增加“校内 / 校外”标识。
- 系统生成编号后不能随意修改，同一个校外老师再次出现时继续使用原编号。

这是目前最推荐的兼容方案。

### 情况 C：无法取得任何老师工号

- 由系统生成内部教师编号，例如 `TEA-2026-0001`。
- 导入前根据姓名、单位、电话、邮箱进行重复检查。
- 遇到同名或信息不完整的老师，由管理员人工确认是否为同一个人。
- 不建议直接使用姓名、手机号、QQ 或邮箱作为唯一编号。

这种方案可以使用，但比正式工号更容易出现重复人员，需要更多人工核对。

## 4. 确认结果出来前的临时要求

- 不要自行猜测、编造或使用连续数字代替正式工号。
- 不要把老师姓名直接填入 `teacher_no`。
- 未取得工号的数据可以先整理姓名、单位、电话、职称和邮箱，但正式导入前必须确定唯一编号规则。
- 如果只是进行系统演示，可以使用明确标注的测试编号；测试数据不得混入正式数据库。

## 5. 建议向开发对话反馈的结论格式

确认后，请按下面任意一种格式反馈：

- “所有指导老师都有正式工号，可以使用工号作为唯一编号。”
- “只有校内老师有工号，校外老师需要系统生成编号。”
- “无法取得老师工号，全部使用系统内部教师编号。”

同时补充：

- 工号从哪里获取。
- 历史项目能否补齐工号。
- 是否存在校外、兼职或退休返聘指导老师。
- 工号是否允许管理员查看，以及是否需要对项目负责人隐藏。

## 6. 当前建议

在学校给出正式结论前，数据库保留 `teacher_no` 字段，但不要把“所有老师一定有工号”作为不可调整的最终假设。

建议优先争取使用正式工号；若只有部分老师有工号，则采用“校内正式工号 + 校外系统编号”的组合方案。
