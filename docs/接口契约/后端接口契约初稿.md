# 后端接口契约初稿

## 基础约定

接口前缀：

```text
http://127.0.0.1:3000/api
```

统一返回格式：

```json
{
  "success": true,
  "code": "OK",
  "message": "ok",
  "data": {},
  "pagination": {
    "page": 1,
    "pageSize": 20,
    "total": 100,
    "totalPages": 5
  }
}
```

失败返回：

```json
{
  "success": false,
  "code": "BAD_REQUEST",
  "message": "错误说明",
  "data": null
}
```

数据库表名、SQL、约束名和本地文件路径不通过接口返回。非预期服务端异常统一返回 `INTERNAL_ERROR`，详细错误只记录在本地服务日志中。

## 常用错误码

- `OK`：成功
- `BAD_REQUEST`：请求参数错误
- `UNAUTHORIZED`：未登录或登录过期
- `INVALID_CREDENTIALS`：账号或密码错误
- `ACCOUNT_LOCKED`：账号因连续登录失败被临时锁定
- `LOGIN_RATE_LIMITED`：当前客户端 IP 的登录请求过于频繁
- `ORIGIN_NOT_ALLOWED`：请求 Origin 不在允许名单中
- `REQUEST_BODY_TOO_LARGE`：JSON 或表单请求体超过服务端上限
- `FORBIDDEN`：无权限
- `NOT_FOUND`：资源不存在
- `ROUTE_NOT_FOUND`：接口地址不存在
- `VALIDATION_ERROR`：业务校验失败
- `DUPLICATE_RESOURCE`：重复数据
- `UPLOAD_TYPE_NOT_ALLOWED`：上传格式不允许
- `UPLOAD_FILE_SIZE_EXCEEDED`：单文件大小超限
- `UPLOAD_FILE_COUNT_EXCEEDED`：单次上传文件数量超限
- `UPLOAD_TOTAL_SIZE_EXCEEDED`：累计上传大小超限
- `DATABASE_UNAVAILABLE`：数据库不可用
- `INTERNAL_ERROR`：服务器内部错误

## 分页约定

列表接口统一使用：

```text
page=1&pageSize=20
```

默认：

- `page=1`
- `pageSize=20`
- 最大 `pageSize=100`

## 字段格式

时间：

- 日期：`YYYY-MM-DD`
- 日期时间：ISO 8601 字符串，例如 `2026-08-05T13:00:00.000Z`
- 前端展示时按 Asia/Shanghai 显示。

金额：

- 数据库存储为 `DECIMAL(12,2)`。
- 接口建议返回字符串，例如 `"3000.00"`，避免 JavaScript 浮点误差。

文件大小：

- 接口返回字节数，例如 `52428800`。

## 登录接口

### POST /auth/login

请求：

```json
{
  "username": "admin",
  "password": "ChangeMe123!"
}
```

响应：

```json
{
  "success": true,
  "code": "OK",
  "message": "ok",
  "data": {
    "user": {
      "id": 1,
      "username": "admin",
      "displayName": "系统管理员",
      "role": "admin",
      "status": "enabled",
      "personId": null,
      "passwordResetRequired": true
    }
  }
}
```

登录成功后由后端设置会话 Cookie：

```text
Set-Cookie: kexie_session=<jwt>; Path=/api; HttpOnly; SameSite=Strict
```

- 前端请求统一使用 `credentials: include`，不读取 JWT，也不再把 JWT 或用户信息写入 `localStorage`。
- `NODE_ENV=production` 时 Cookie 同时启用 `Secure`，正式环境必须通过 HTTPS 访问。
- JWT 内包含 `tokenVersion`。每个受保护请求都会查询数据库，校验账号存在、未删除、已启用、角色一致、版本一致。
- 为兼容内部检查脚本，后端认证中间件仍可读取带 `tokenVersion` 的 `Authorization: Bearer <token>`；浏览器登录流程只使用 HttpOnly Cookie。
- 登录接口按反向代理解析后的客户端 IP 限流。默认 15 分钟内普通登录最多 20 次；已识别为管理员账号的登录最多 10 次。
- 同一账号连续 5 次密码错误后返回 HTTP 423 和 `ACCOUNT_LOCKED`。负责人默认锁定 15 分钟，管理员默认锁定 30 分钟；到期后自动解锁，登录成功后清空失败次数、锁定时间和最后失败时间。
- IP 频率超限返回 HTTP 429 和 `LOGIN_RATE_LIMITED`。账号不存在、停用或手工锁定时仍统一返回 `INVALID_CREDENTIALS`，不向客户端暴露账号状态。
- 浏览器请求的 `Origin` 必须属于 `CORS_ORIGINS`；不在白名单时返回 HTTP 403 和 `ORIGIN_NOT_ALLOWED`。非浏览器脚本可以不发送 Origin。

### GET /auth/me

返回当前登录用户。

### POST /auth/change-password

请求：

```json
{
  "oldPassword": "old-password",
  "newPassword": "new-password"
}
```

修改成功后 `token_version` 递增，旧 Cookie/JWT 立即失效，响应会设置包含新版本的新 Cookie。

### POST /auth/logout

退出当前账号。后端递增 `token_version` 并清除会话 Cookie，因此退出前的旧 Cookie/JWT 不能再次使用。

当 `passwordResetRequired=true` 时，后端只允许访问：

- `GET /auth/me`
- `POST /auth/change-password`
- `POST /auth/logout`

访问其他业务接口返回 HTTP 403 和错误码 `PASSWORD_CHANGE_REQUIRED`。

## 账号接口初稿

后续对话 5 实现：

- `GET /accounts`：管理员查询账号列表。
- `POST /accounts`：管理员创建负责人或管理员账号。
- `PATCH /accounts/:id/status`：启用、禁用或锁定账号。
- `POST /accounts/:id/reset-password`：管理员重置密码，返回一次性初始密码。
- `DELETE /accounts/:id`：管理员软删除账号；不能删除自己。

停用、锁定、重新启用、密码重置和软删除都会递增目标账号的 `token_version`。密码重置会重新启用账号并要求首次改密；软删除会将账号设为停用并写入 `deleted_at`。

第一版账号规则：

- 角色包括 `admin`、`applicant` 和 `project_owner`。
- 指导老师不登录。
- 管理员权限第一版不细分。
- 管理员只能创建管理员或既有正式项目负责人账号，不能代申请人注册。
- 申请人通过开放注册创建 `applicant` 账号；学校通过并成功转项目后升级为 `project_owner`。
- 管理员创建或重置的账号首次登录必须改密；自主注册账号不要求首次改密。

## 材料任务接口初稿

`material_tasks` 表示统筹任务文件夹，`material_categories` 在接口中作为其下的单文件子任务继续使用，以兼容已有提交和审核数据。

- `GET /material-tasks`
- `GET /material-tasks/options`
- `POST /material-tasks`
- `PUT /material-tasks/:id`
- `PATCH /material-tasks/:id/status`
- `GET /material-tasks/:id/templates`
- `GET /material-tasks/:id/templates/:attachmentId/download`

新建、编辑任务时使用结构化 `fileTasks`：

```json
{
  "taskName": "2026 年结项材料",
  "taskDescription": "统一收集每个项目的结项文件",
  "projectScopeType": "custom",
  "projectYear": null,
  "projectGroup": null,
  "projectIds": [12, 15],
  "deadlineAt": "2026-12-20 23:59:59",
  "maxTaskProjectMb": 500,
  "status": "draft",
  "fileTasks": [
    {
      "id": 21,
      "categoryName": "项目申报书",
      "taskDescription": "上传最终盖章版",
      "allowedExtensions": ["pdf", "docx"],
      "maxFileMb": 20,
      "hasTemplate": true,
      "isRequired": true,
      "sortOrder": 0
    }
  ]
}
```

范围类型：

- `all`：全部项目。
- `year`：指定年度，使用 `projectYear`。
- `group`：指定现有组别，使用 `projectGroup`。
- `custom`：指定项目，使用 `projectIds` 数组。

`GET /material-tasks/options` 返回数据库中的年度、组别和项目选项，前端会显示年度/组别对应的项目数，并支持多选指定项目。

列表接口同时返回 `fileTasks`、`projectIds`、`submissionCount` 和 `editable`。每个子文件任务独立保存允许格式、单文件大小、是否提供模板和已有模板文件。任务尚未关闭且没有任何提交记录时 `editable=true`，包括已经发布但尚未收到提交的任务；已有提交或已关闭时只能查看。为兼容旧调用，后端仍可读取旧的 `categories` 字段，但新页面和新接口文档统一使用 `fileTasks`。

已提供基础模板下载接口：

```text
GET /material-tasks/:taskId/templates/:attachmentId/download
```

负责人按具体子任务查询模板：

```text
GET /material-tasks/:taskId/templates?categoryId=:fileTaskId
```

## 文件上传接口

### POST /uploads/task-templates

管理员上传材料任务模板附件。

请求类型：`multipart/form-data`

字段：

- `taskId`：材料任务 ID
- `categoryId`：子文件任务 ID
- `files`：一个或多个文件

限制：

- 单文件默认不超过 50MB。
- 单次最多上传 10 个文件。
- 支持 PDF、DOC、DOCX、XLS、XLSX、PPT、PPTX、JPG、JPEG、PNG、ZIP。

### POST /uploads/submissions

负责人提交材料。

请求类型：`multipart/form-data`

字段：

- `taskId`：材料任务 ID
- `projectId`：项目 ID
- `categoryId`：子文件任务 ID（数据库中仍对应 `material_categories.id`）
- `file`：且仅有一个文件

限制：

- 单文件默认不超过 50MB。
- 每个项目、每个子文件任务、每次提交只能上传 1 个文件。
- 被退回后可重新提交，新提交会形成新版本，历史提交继续保留。
- 单个项目在一个材料任务下累计默认不超过 500MB。

## 标准工作簿导入接口初稿

完整导入分为“预检查”和“确认入库”两步，预检查不会修改数据库。

### POST /imports/standard-workbook/validate

请求类型：`multipart/form-data`

- `file`：标准 `.xlsx` 工作簿，最大 20MB

成功后返回临时批次编号和检查摘要：

```json
{
  "success": true,
  "code": "OK",
  "message": "校验完成",
  "data": {
    "batchId": "import-batch-id",
    "valid": false,
    "expiresAt": "2026-08-05T16:00:00.000Z",
    "sheets": [
      {
        "name": "1_项目",
        "totalRows": 100,
        "validRows": 98,
        "errorRows": 2
      }
    ]
  }
}
```

### GET /imports/:batchId/errors/download

下载预检查错误清单。每条错误包含工作表名称、Excel 行号、字段名、原值和错误原因。

### POST /imports/:batchId/commit

确认正式导入：

```json
{
  "mode": "create_only"
}
```

`mode` 可选：

- `create_only`：默认，仅新增；数据库已有唯一编号时拒绝导入。
- `upsert`：明确用于修正数据；已有数据按唯一编号更新，不存在的数据新增。

只有预检查全部通过的批次可以提交。提交过程使用数据库事务，失败时整批回滚。

## 简化导入、导入记录与回滚接口

本组接口仅允许管理员访问。标准工作簿接口继续兼容；新页面默认使用简化导入。

### GET /imports/field-options

返回页面可用模块、固定定位列、可选择字段和默认选择字段：

```json
{
  "modules": [
    {
      "key": "checks",
      "title": "检查记录",
      "kind": "update",
      "fixedFields": [
        { "field": "project_code", "label": "项目编号" },
        { "field": "check_phase", "label": "检查阶段" }
      ],
      "fields": [
        { "field": "research_log_count", "label": "研究日志数量", "clearable": false },
        { "field": "rating", "label": "评级", "clearable": true }
      ],
      "defaultFields": ["research_log_count", "rating", "checked_at", "remark"]
    }
  ]
}
```

### GET /imports/templates/:type/download

下载简化导入模板。

`type` 可选：

- `simple-projects`：新建项目导入。
- `project-field-update`：项目基本信息。
- `people`：人员信息。
- `project-participations`：项目人员关系。
- `checks`：检查记录。
- `reimbursements`：报销记录。

除 `simple-projects` 外，其他类型必须通过 `fields` 查询参数指定修改字段。服务端自动把该模块的固定定位列放在模板最前面，模板表头使用中文。

示例：

```text
GET /api/imports/templates/project-field-update/download?fields=title,status
```

### POST /imports/:type/validate

上传简化模板并预检查。请求类型：`multipart/form-data`。

`type` 可选：

- `simple-projects`
- `project-field-update`
- `people`
- `project-participations`
- `checks`
- `reimbursements`

更新模块统一遵守：空单元格不修改原值，填写 `[清空]` 才清空允许为空的字段。项目人员关系中的空“操作”表示新增或更新，填写“删除”或“移除”表示移除关系。

响应：

```json
{
  "success": true,
  "code": "OK",
  "message": "预检查完成",
  "data": {
    "batchId": "uuid",
    "valid": true,
    "errorCount": 0,
    "summary": {
      "valid": true,
      "total": 10,
      "create": 4,
      "update": 3,
      "remove": 1,
      "skip": 2,
      "error": 0,
      "conflict": 0
    }
  }
}
```

预检查会永久保存批次、原始文件、SHA-256 校验值、错误清单、逐行记录和字段差异。未确认的批次状态为 `validated`。

### POST /imports/:batchId/commit

确认正式导入。简化导入批次无需额外请求体；标准工作簿批次继续支持：

```json
{
  "mode": "create_only"
}
```

正式导入使用数据库事务。任一关键步骤失败整批回滚，不保留半导入数据。

### GET /imports

分页查询导入记录，支持：

```text
page=1&pageSize=20&type=project_field_update&status=committed
```

记录包含批次编号、导入类型、状态、原始文件名、文件校验值、文件大小、统计结果、创建时间、确认时间和回滚时间。

### GET /imports/:batchId

查看批次详情，包含：

- 批次基础信息。
- 错误清单。
- 每行记录的 `entityType`、`entityKey`、`operationType`、`status`、`rowNumber`、`beforeSnapshot`、`afterSnapshot`。
- 字段级差异 `fields`。

### GET /imports/:batchId/original/download

下载该批次原始上传文件。服务端会验证文件真实路径位于导入文件保存目录内。

### GET /imports/:batchId/errors/download

下载错误清单 CSV。标准工作簿临时批次和简化导入永久批次都支持。

### GET /imports/:batchId/diff/download

导出字段差异 CSV，列包括 Excel 行号、对象类型、唯一识别、操作、状态、字段、原值、新值和说明。

### POST /imports/:batchId/rollback

整批回滚已正式导入且未回滚的批次。

回滚规则：

- 回滚生成新的 `rollback` 类型批次，不删除原历史。
- 只有当前值仍等于该批次导入后值时才自动恢复。
- 当前值已被后续操作修改时，标记 `conflict` 并跳过。
- 第一版支持项目、人员、项目人员关系、检查记录和报销记录恢复，不提供强制覆盖冲突。

响应：

```json
{
  "rollbackBatchUuid": "uuid",
  "total": 10,
  "restore": 8,
  "conflict": 2
}
```

## 归档模板接口

本组接口仅允许管理员访问。

归档模板版本 2 采用“项目根目录 + 目录树 + 已放置子任务”结构：

```json
{
  "version": 2,
  "projectRootRule": "{项目编号}-{作品名称}",
  "preserveEmptyFolders": false,
  "defaultFileNameRule": "{材料类别}_{原文件名}",
  "nodes": [
    {
      "id": "folder-1",
      "type": "folder",
      "nameRule": "01-立项材料",
      "children": [
        {
          "id": "task-1",
          "type": "task",
          "materialTaskId": 3,
          "fileTaskId": 12,
          "materialTaskName": "2026 年结项材料",
          "fileTaskName": "项目申报书",
          "fileNameRule": "{项目编号}_{材料类别}_{原文件名}"
        }
      ]
    }
  ]
}
```

约束：

- 每个项目使用同一模板，并先生成一个 `projectRootRule` 项目根文件夹。
- `folder` 节点可递归嵌套，最多 8 层、总节点最多 300 个。
- `task` 节点指向一个真实子文件任务；同一子文件任务在一个模板中只能出现一次。
- `preserveEmptyFolders=true` 时会在 ZIP 中保留该项目模板下的空目录。
- 旧版 `version: 1` 平铺模板和历史导出快照继续支持读取与导出；前端编辑旧模板时会引导转换为版本 2 并重新放置子任务。

支持的占位字段：

- 导出与排序：`{项目序号}`、`{项目序号两位}`、`{项目序号三位}`、`{材料序号}`、`{材料序号两位}`、`{导出日期}`、`{导出批次}`。
- 项目信息：`{年度}`、`{组别}`、`{项目编号}`、`{作品名称}`、`{项目类别}`、`{立项日期}`。
- 负责人和团队：`{负责人}`、`{负责人学号工号}`、`{负责人学院单位}`、`{负责人电话}`、`{项目成员}`、`{指导教师}`。
- 材料和审核：`{材料任务}`、`{材料类别}`、`{原文件名}`、`{原扩展名}`、`{提交日期}`、`{审核通过日期}`。

项目序号按一次导出中的项目稳定顺序生成，同一项目下所有材料使用相同序号；两位和三位字段分别补零为 `01`、`001`。材料序号按模板目录树中子文件任务的顺序生成。`{原文件名}` 不含扩展名，系统最终仍自动保留原扩展名。

接口：

- `GET /archive-templates`：分页查询，支持 `keyword`、`status=enabled|disabled`。
- `GET /archive-templates/task-library`：返回统筹任务及其子文件任务，供模板编辑器右侧任务库使用。
- `POST /archive-templates/preview`：校验配置并返回示例目录和示例文件名。
- `POST /archive-templates`：新建模板。
- `PUT /archive-templates/:id`：编辑模板。
- `PATCH /archive-templates/:id/status`：启用或停用模板。
- `DELETE /archive-templates/:id`：软删除模板，同时将其状态改为停用；模板不再出现在可用列表或新建导出中，已有导出记录继续保留。

新建或编辑请求：

```json
{
  "templateName": "默认年度材料归档模板",
  "status": "enabled",
  "templateConfig": {
    "version": 2,
    "projectRootRule": "{项目编号}-{作品名称}",
    "preserveEmptyFolders": false,
    "defaultFileNameRule": "{材料类别}_{原文件名}",
    "nodes": [
      {
        "id": "folder-final",
        "type": "folder",
        "nameRule": "03-结项材料",
        "children": [
          {
            "id": "task-budget",
            "type": "task",
            "materialTaskId": 3,
            "fileTaskId": 12,
            "materialTaskName": "结项材料",
            "fileTaskName": "经费决算表",
            "fileNameRule": "{材料类别}_{原文件名}"
          }
        ]
      }
    ]
  }
}
```

服务端会拒绝未知占位字段、空目录名、空文件命名规则、重复节点 ID、重复子任务和无任何已放置子任务的模板。

## 材料整理包导出接口

本组接口仅允许管理员访问。

### GET /archive-exports/options

返回结构化导出表单所需的年度、组别、已发布或已关闭材料任务、项目选项。

### POST /archive-exports

创建数据库队列驱动的导出任务，成功创建后返回 HTTP `202` 和 `queued` 状态。API 只负责校验范围和创建排队记录，不在请求内生成 ZIP；后台归档 Worker 会按队列处理任务，第一版同一时间只处理一个大型导出。

```json
{
  "archiveTemplateId": 1,
  "scope": {
    "years": [2026],
    "groups": ["创新组"],
    "materialTaskIds": [3, 4],
    "projectIds": [12, 15]
  },
  "remark": "2026 年中期检查材料移交"
}
```

四类筛选均使用数组。空数组表示不使用该维度继续缩小范围；前端为防止误导出，要求至少选择一个材料任务，并至少选择年度、组别或项目中的一类。

后台会限制同时排队数量、单次导出项目数量和源文件总量，并在创建任务前检查导出目录所在磁盘的可用空间。

导出规则：

- 版本 2 模板只处理已经放入目录树的子文件任务；导出表单中的统筹任务筛选必须属于当前模板。
- 对每个“统筹任务 + 项目 + 子文件任务”，只取审核时间最新的一次 `approved` 提交。
- 更晚出现的待审核或退回提交不会覆盖此前已经审核通过的正式版本。
- 待审核、退回、未提交材料不进入正式材料目录。
- 没有审核通过版本、审核通过版本没有文件、文件丢失或文件路径异常时，写入 ZIP 根目录的 `缺失材料报告.xlsx`；报告列包含负责人和负责人电话。
- 结构化筛选没有匹配到任何应收材料时，也会生成明确的缺失报告条目，不返回没有说明的空 ZIP。
- ZIP 根目录始终包含 `导出材料清单.xlsx` 和 `导出说明.txt`；材料清单同样包含负责人电话。
- Windows 非法文件名字符会被替换，设备保留名会被改写，重名文件自动追加 `_2`、`_3`。

### GET /archive-exports

分页查询导出记录，支持 `status=queued|processing|success|failed`。

记录包含：

- `exportStatus`
- `failureReason`
- `attemptCount`
- `maxAttempts`
- `startedAt`
- `heartbeatAt`
- `workerId`
- `exportScope` 与 `exportScopeLabel`
- `exportSummary.expectedMaterialCount`
- `exportSummary.approvedMaterialCount`
- `exportSummary.exportedFileCount`
- `exportSummary.missingCount`
- `exportSummary.missingReportIncluded`
- `downloadable`

### POST /archive-exports/:id/retry

管理员可将 `failed` 状态的任务重新加入队列。重试会清空失败原因、开始时间、心跳时间和 Worker 标识，并将尝试次数重置为 0。

### GET /archive-exports/:id

查询单条导出任务状态和详情，前端可用此接口轮询。

### GET /archive-exports/:id/download

仅 `success` 状态且 ZIP 尚未按保存期限清理时可下载。服务端会再次验证数据库记录的文件路径属于系统 `EXPORT_ROOT` 导出目录，拒绝目录外路径和不存在的文件。

## 申请人注册与立项审批闭环

### 开放注册

`POST /auth/register` 不需要登录。请求字段：`username`、`password`、`studentNo`、`name`、`college`，可选 `phone`、`email`。

- 每 IP 默认每小时最多 8 次。
- 密码 10–72 位且必须包含字母和数字，使用 bcrypt cost 12 保存。
- 学号和账号分别受数据库唯一约束；冲突统一返回 HTTP 409 / `DUPLICATE_RESOURCE`，不返回现有账号资料。
- 成功后创建 student 人员和最小权限 `applicant` 账号，不自动登录。
- 安全日志只记录事件、IP 和新用户 ID，不记录密码或完整请求体。

### 批次配置

- `GET /applications/batches/open`：申请人查看当前可申请批次。
- `GET /applications/batches`：管理员查看批次及申请、待审、合格、冻结、转项目统计。
- `GET /applications/batches/:id`：查看动态字段和材料要求；applicant 仅能查看开放批次或自己已有申请的批次。
- `POST /applications/batches`：管理员创建草稿批次。
- `PUT /applications/batches/:id`：管理员编辑无申请的草稿批次。
- `PATCH /applications/batches/:id/status`：`draft -> open|closed`、`open -> closed`、`closed -> open`；历史批次不能开放。
- `POST /applications/batches/:id/requirements/:requirementId/template`：管理员上传材料模板。
- `GET /applications/batches/:id/requirements/:requirementId/template/download`：有批次访问权的 admin/applicant 下载模板。

批次请求中的 `applicationSchema` 最多 40 个字段，每项包括 `key`、`label`、`type=text|textarea|number|date|select`、`required`、`options`。`materialRequirements` 最多 30 项，每项包括唯一 `code`、名称、必交标志、允许扩展名和单文件 MB 上限。

### 申请人申请与材料版本

- `GET /applications/mine`：仅返回当前 applicant 的申请。
- `POST /applications`：在开放批次创建草稿；正式项目负责人或已有进行中申请时拒绝。
- `PUT /applications/:id`：仅本人且状态为 `draft|returned` 时保存。
- `POST /applications/:id/materials/:requirementId`：仅本人上传一个新材料版本，`multipart/form-data` 字段 `file`。
- `GET /applications/:id/materials`：本人或管理员查看全部版本及版本审核信息。
- `GET /applications/:id/materials/:fileId/download`：本人或管理员下载，路径必须位于上传根目录。
- `POST /applications/:id/submit`：校验本次版本所有必交材料后正式提交并递增 `submissionVersion`。
- `POST /applications/:id/withdraw`：冻结前本人撤回；冻结后只能由管理员撤回报送且必须填写原因。
- `GET /applications/:id/audit`：本人或管理员查看该申请审计轨迹。

同一申请累计上传默认不超过 `MAX_APPLICATION_TOTAL_MB=200`。服务端同时校验全局扩展名、材料扩展名、全局大小、材料大小、累计容量、申请归属和批次状态；保存原文件名、受控路径、字节数、MIME、SHA-256、上传人、上传时间、提交版本和文件版本。文件行不可更新或删除。

### 管理员材料合格性审核

- `GET /applications?batchId=&status=&page=&pageSize=`：管理员申请列表。
- `POST /applications/:id/review`：请求 `{ "result": "eligible|returned", "reason": "..." }`。

只有 `submitted` 可审核。退回必须填写原因；合格事件的审计载荷固定带 `meaning=material_eligibility_only`，界面不得显示为学校批准。

### 冻结报送、导出与撤回

- `POST /applications/batches/:id/export`：锁定批次和所有 `eligible` 申请，原子转为 `frozen`，保存快照并生成学校 Excel 和材料 ZIP。
- `GET /applications/exports`：管理员查看报送记录。
- `GET /applications/exports/:id/download/workbook|package`：下载报送 Excel 或材料包。
- `POST /applications/exports/:id/recall`：必须提供 `reason`；把该报送中的 `frozen` 申请退回 `eligible`，记录不可变审计事件。

Excel 对以 `= + - @` 开头的用户文本加前缀，避免公式注入；ZIP 文件夹和文件名清理路径字符；源文件路径必须属于上传根目录。

如果冻结事务已提交但 Excel/ZIP 生成失败，服务端在补偿事务中把本次仍为 `frozen` 的申请恢复为 `eligible`，批次恢复为 `closed`，报送记录标记 `failed`，删除半成品并写 `report_batch_export_failed_recovered` 审计事件；补偿失败会显式返回组合错误，禁止把冻结状态伪装成成功。

### 学校结果与历史首次立项

- `POST /applications/batches/:id/results/validate`：上传单工作表 `.xlsx`（最多 5000 个数据行、50 列），计算大小和 SHA-256，执行预检查，不写正式项目。合法文件保留作为结果凭据；无效文件仅保留文件名、大小、SHA-256、错误摘要和标准化行，临时原文件立即删除，`storage_path=NULL`。
- `POST /applications/batches/:id/results/manual`：管理员逐条录入，生成持久化的人工录入记录并预检查。
- `POST /applications/result-imports/:id/commit`：仅提交 `valid` 的预检查批次，整批数据库事务处理。

学校结果模板识别中文或英文表头：学号、学校结果、项目编号、立项日期、备注。结果只接受“通过/未通过”或 `approved/rejected`；学校通过必须提供项目编号。

提交当前申请结果时：

1. 锁定导入、批次和申请。
2. 学校通过：检查学生和项目负责人唯一约束，创建或关联正式项目，建立唯一 owner，写 `project_approval_sources`，更新申请为 `converted`，把账号升级为 `project_owner` 并递增 `token_version`。
3. 学校未通过：申请转为 `school_rejected`，不创建项目。
4. 写逐条及批次审计事件；任一步失败整批回滚。

管理员直接新增/状态转换、标准工作簿、简化导入、导入回滚、历史首次名单和学校结果转项目统一遵守：`draft` 可无负责人，`active/checking/completed/archived/stopped` 在事务提交时必须恰好一名未删除学生负责人；标准/简化导入在整批人员关系处理后验证，失败回滚整批。

历史首次批次设置 `isHistorical=true` 且 `approvalRound=first`，不向申请人开放。正式名单预检查要求学号、姓名、项目编号、项目名称；提交时可关联已有项目或创建项目和人员，不创建 applicant 账号。来源固定为 `historical_official_list`，材料状态固定为 `missing_historical`。

正式项目追溯接口：`GET /applications/projects/:projectId/source`。管理员可查全库；project_owner 只能查自己负责项目；applicant 不得访问正式项目。
