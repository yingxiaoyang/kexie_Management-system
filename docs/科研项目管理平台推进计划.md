## 1. 项目目标

本项目采用“边建设、边学习、边交接”的方式推进。

第一版目标是做出一个可真实试用的科研项目材料管理网站，服务对象为：

- 项目负责人
- 管理员
- 只读查看人员

核心功能包括：

- 项目与人员管理
- 材料收集任务发布
- 项目负责人材料提交
- 管理员审核与退回
- 可视化归档模板配置
- 材料整理包导出
- 人员联系方式查询
- 项目参与规则校验

当前主对话作为总控对话，负责确认需求、拆分任务、汇总其他对话结果、维护总体方案，避免多个对话各做各的。

## 2. 技术路线

- 前端：继续使用已有 Vue 3 + Vite 项目
- UI：继续使用 Element Plus
- 路由：使用已有 Vue Router 依赖，补全路由配置
- 后端：Node.js，建议在根目录新增 `server` 或 `backend` 目录
- 数据库：MySQL
- MySQL 运行方式：Docker。当前 Docker Desktop、WSL 2 和 MySQL 容器环境已安装并验证
- 文件存储：先做“抽象接口 + 本地模拟”，后续可替换为学校网盘、MinIO、阿里云 OSS、腾讯 COS 等对象存储或网盘服务
- 版本管理：Git + GitHub。当前本地仓库、`main` 分支和 GitHub 远程仓库已配置

建议目录方向：

- `code\kexie_vue`：已有前端项目，继续保留
- `server` 或 `backend`：后端 Node 服务
- `docs`：需求、数据表设计、运行说明、交接记录
- `storage`：本地模拟文件存储目录，后续可替换为对象存储
- `database`：数据库初始化脚本、迁移脚本、种子数据

## 3. 用户与权限设计

### 3.1 项目负责人

负责人登录后进入门户式工作台，重点看到：

- 我的项目
- 待提交材料
- 截止时间
- 材料提交状态
- 退回原因
- 提交记录
- 本项目成员和指导老师联系方式

项目负责人只能查看自己项目相关的人员联系方式，不能查看全校人员库。

### 3.2 管理员

管理员登录后进入后台管理系统，重点操作：

- 项目管理
- 人员库管理
- 账号管理
- 材料任务管理
- 材料审核
- 归档模板配置
- 材料整理包导出
- 人员联系方式搜索
- 项目参与规则配置

管理员可以查看全库联系方式。

### 3.3 只读查看人员

只读查看人员可以查看和下载授权范围内的数据，但不能修改：

- 项目
- 人员
- 材料任务
- 审核结果
- 归档模板

## 4. 数据拆分设计

现有 Excel 表不建议原样做成一张大表，而是拆成多个模块。

### 4.1 项目基础信息

来自现有表格和新增字段：

- 项目所属年度
- 组别
- 项目编号
- 作品名称
- 项目类别
- 立项时间
- 立项类型：首次立项 / 补充立项
- 项目状态
- 备注

### 4.2 人员库

人员库覆盖：

- 学生
- 指导老师

学生使用学号作为唯一标识，老师使用工号作为唯一标识。

学生字段：

- 姓名
- 学院
- 学号
- 电话
- QQ
- 账号状态

指导老师字段：

- 姓名
- 工号
- 单位
- 联系方式
- 职务 / 职称
- email

### 4.3 项目参与关系

用于表达某个人在某个项目中的身份，而不是把负责人和成员信息塞在项目表的一个单元格里。

参与关系包括：

- 项目
- 人员
- 角色：项目负责人 / 项目成员 / 指导老师
- 是否主要负责人
- 加入时间
- 备注

这样可以支持：

- 按人搜索参与了哪些项目
- 按项目查看所有相关人员
- 检查一个人是否超出负责人或成员数量限制
- 快速查询联系方式和学号

### 4.4 检查记录

从现有表格中拆出：

- 中期检查研究日志数量
- 中期检查评级
- 阶段检查研究日志数量
- 阶段检查评级

### 4.5 报销记录

从现有表格中拆出：

- 报销额度
- 中期报销申报金额
- 中期报销实际金额
- 阶段报销申报金额
- 阶段报销实际金额
- 剩余额度

### 4.6 材料提交记录

新增并重点使用：

- 材料任务
- 项目
- 材料类别
- 提交人
- 文件
- 材料提交状态：未提交 / 已提交 / 退回 / 逾期
- 审核状态：待审核 / 通过 / 退回
- 退回原因
- 最后提交时间
- 最后审核时间

### 4.7 归档导出记录

新增：

- 导出人
- 导出时间
- 使用的归档模板
- 导出范围
- 导出文件包路径
- 导出备注

## 5. 核心功能模块

### 5.1 项目导入

第一版不直接解析混在一个单元格里的负责人和成员信息。

建议整理成三个规范模板后导入：

- 项目表
- 人员表
- 项目参与关系表

这样导入更稳定，也方便后续搜索、统计和规则校验。

### 5.2 人员管理

管理员可以：

- 新增人员
- 编辑人员信息
- 搜索姓名、学号、工号、电话、QQ、学院、单位
- 查看某个人参与的项目
- 查看某个人担任负责人或成员的数量

### 5.3 项目参与规则

管理员可以配置规则，例如：

- 一个人最多担任 1 个项目负责人
- 一个人最多担任 2 个项目成员

导入或编辑项目参与关系时，系统自动检查并拦截违规数据。

### 5.4 材料任务

管理员可以创建材料收集任务：

- 任务名称
- 适用项目范围
- 材料清单
- 固定材料类别
- 自定义材料类别
- 截止时间
- 文件格式限制
- 文件大小限制

项目负责人登录后可以看到自己项目的待提交任务。

### 5.5 材料审核

管理员可以对提交材料执行：

- 通过
- 退回

退回时必须填写退回原因。

项目负责人可以查看退回原因并重新提交。

### 5.6 归档模板与导出

管理员可以通过可视化方式拼装目录层级和文件命名规则。

示例规则：

- 按年度分目录
- 按组别分目录
- 按项目编号和作品名称生成项目文件夹
- 按材料类别归类
- 文件名包含项目编号、作品名称、负责人、材料名称

系统根据模板一键生成材料整理包，并记录归档导出记录。

## 6. 界面方向

### 6.1 项目负责人端

负责人端需要更美观，偏门户式首页。

重点不是复杂表格，而是让负责人快速看到：

- 当前要做什么
- 哪些材料还没交
- 哪些材料被退回
- 截止时间
- 自己负责的项目
- 项目相关人员联系方式

### 6.2 管理员端

管理员端偏后台管理系统，简洁明了。

重点是：

- 表格
- 筛选
- 搜索
- 批量导入
- 批量审核
- 状态查看
- 导出整理

## 8. 对话间如何避免冲突

- 当前对话作为总控对话，所有关键决定先在这里确认。
- 每个对话只负责自己的范围，不跨界修改别人的核心内容。
- 涉及公共配置的内容只由一个对话主改，例如数据库连接、启动命令、项目目录结构。

  - 完成了什么

  - 怎么运行或验证
  - 还缺什么
  - 下一个对话需要知道什么
- 共享决定统一写入项目文档：
  - `docs\科研项目管理平台推进计划.md`
  - `docs\需求说明.md`

## 11. 当前已确认的默认假设

- 第一版先做真实试用版，不直接追求学校正式上线级别。
- 暂不接学校统一身份认证，账号由管理员创建。

- 维护学习方式先按“维护导向”讲解，如果觉得太粗，再切换成从零教学。
- 已有前端项目继续使用，不从零新建 Vue 项目。
