## 1. 项目目标

本项目采用“边建设、边学习、边交接”的方式推进。

第一版目标是做出一个可真实试用的科研项目材料管理网站，服务对象为：

- 项目负责人
- 管理员

核心功能包括：

- 项目与人员管理
- 材料收集任务发布
- 项目负责人材料提交
- 管理员审核与退回
- 可视化归档模板配置
- 材料整理包导出
- 人员联系方式查询
- 项目参与规则校验

当前主对话作为总控对话，负责确认需求、拆分任务、汇总其他对话结果、维护总体方案，避免多个对话各做各的。

## 3. 用户与权限设计

### 3.1 项目负责人

负责人登录后进入门户式工作台，重点看到：

- 我的项目
- 待提交材料
- 截止时间
- 材料提交状态
- 退回原因
- 提交记录
- 本项目成员和指导老师联系方式

项目负责人只能查看自己项目相关的人员联系方式，不能查看全校人员库。

### 3.2 管理员

管理员登录后进入后台管理系统，重点操作：

- 项目管理
- 人员库管理
- 账号管理
- 材料任务管理
- 材料审核
- 归档模板配置
- 材料整理包导出
- 人员联系方式搜索
- 项目参与规则配置

管理员可以查看全库联系方式。

### 3.3 第一版账号规则

- 当前保留申请人、项目负责人和管理员三类账号，不设置只读查看人员账号。
- 指导老师只作为人员资料和项目参与关系保存，第一版不创建指导老师登录入口。
- 允许创建多个管理员账号，第一版管理员权限保持一致，暂不细分超级管理员和普通管理员。
- 申请人必须自主注册为 `applicant`，管理员不知道申请人名单且不能代为预建申请人账号。
- 当前不接统一身份认证、邮件或短信验证码，注册资料视为本人自报；账号只能访问自己的申请、材料与结果。
- 学校正式通过并在事务中建立项目后，申请人账号升级为 `project_owner`。
- 既有项目负责人账号仍可由管理员维护；管理员生成或重置密码后首次登录必须修改密码。
- 项目负责人忘记密码时，由管理员执行密码重置。

## 4. 数据拆分设计

现有 Excel 表不建议原样做成一张大表，而是拆成多个模块。

### 4.1 项目基础信息

来自现有表格和新增字段：

- 项目所属年度
- 组别
- 项目编号
- 作品名称
- 项目类别
- 立项时间
- 立项类型：首次立项 / 补充立项
- 一个项目只能立项一次；首次立项和补充立项互斥，不会在同一项目下同时存在两次立项记录。
- 项目状态
- 备注

### 4.2 人员库

人员库覆盖：

- 学生
- 指导老师

学生使用学号作为唯一标识，老师使用工号作为唯一标识。

指导老师是否都能取得正式工号仍需向学校相关人员确认。在结论明确前，不随意编造工号；具体确认内容和备选处理方案见 `docs\指导老师工号确认须知.md`。

学生字段：

- 姓名
- 学院
- 学号
- 电话
- QQ
- 账号状态

指导老师字段：

- 姓名
- 工号
- 单位
- 联系方式
- 职务 / 职称
- email

### 4.3 项目参与关系

用于表达某个人在某个项目中的身份，而不是把负责人和成员信息塞在项目表的一个单元格里。

参与关系包括：

- 项目
- 人员
- 角色：项目负责人 / 项目成员 / 指导老师
- 是否主要负责人
- 加入时间
- 备注

这样可以支持：

- 按人搜索参与了哪些项目
- 按项目查看所有相关人员
- 检查一个人是否超出负责人或成员数量限制
- 快速查询联系方式和学号

### 4.4 检查记录

从现有表格中拆出：

- 中期检查研究日志数量
- 中期检查评级
- 阶段检查研究日志数量
- 阶段检查评级

### 4.5 报销记录

从现有表格中拆出：

- 报销额度

- 中期报销实际金额
- 阶段报销申报金额
- 阶段报销实际金额
- 剩余额度

### 4.6 材料任务、任务模板与提交记录

新增并重点使用：

- 统筹材料任务文件夹
- 是否提供任务模板
- 任务模板附件：允许一个任务上传多个模板文件
- 模板原始文件名、存储路径、文件大小、文件类型、上传时间
- 项目
- 子文件任务（数据库兼容使用原材料类别表）
- 提交人
- 文件
- 材料提交状态：未提交 / 已提交 / 退回 / 逾期
- 审核状态：待审核 / 通过 / 退回
- 退回原因
- 最后提交时间
- 最后审核时间

### 4.7 归档导出记录

新增：

- 导出人

- 导出范围
- 导出文件包路径

## 5. 核心功能模块

### 5.1 项目导入

第一版不直接解析混在一个单元格里的负责人和成员信息。

建议整理成三个规范模板后导入：

- 项目表
- 人员表
- 项目参与关系表

这样导入更稳定，也方便后续搜索、统计和规则校验。

### 5.2 人员管理

管理员可以：

- 新增人员
- 编辑人员信息
- 搜索姓名、学号、工号、电话、QQ、学院、单位
- 查看某个人参与的项目
- 查看某个人担任负责人或成员的数量

### 5.3 项目参与规则

管理员可以配置规则，例如：

- 一个人最多担任 1 个项目负责人
- 一个人最多担任 2 个项目成员

导入或编辑项目参与关系时，系统自动检查并拦截违规数据。

### 5.4 材料任务

管理员可以创建材料收集任务：

- 统筹任务名称和说明
- 适用项目范围
- 统筹任务下可新增、删除和排序多个子文件任务
- 每个子文件任务可填写提交说明和必交状态
- 每个项目、每个子文件任务、每次提交只允许一个文件
- 截止时间
- 文件格式限制
- 文件大小限制
- 是否提供模板文件
- 模板附件：允许上传多个，例如报告模板、研究日志模板、报销汇总表模板

项目负责人登录后可以看到自己项目的待提交任务。

如果任务提供模板，负责人可以在任务详情和材料提交页面下载对应模板。管理员编辑任务时可以替换或补充模板，已经提交的材料不受模板更新影响。

第一版默认上传限制：

- 支持 PDF、DOC、DOCX、XLS、XLSX、PPT、PPTX、JPG、JPEG、PNG、ZIP。
- 单个文件不超过 50MB。
- 单个项目在一个材料任务下累计上传不超过 500MB。
- 管理员发布任务时可以在默认范围内进一步限制文件类型和大小。

### 5.5 材料审核

管理员可以对提交材料执行：

- 通过
- 退回

退回时必须填写退回原因。

项目负责人可以查看退回原因并重新提交。

### 5.6 归档模板与导出

管理员可以通过可视化方式拼装目录层级和文件命名规则。

当前实际实现采用一个模板服务所有项目：每个项目先生成 `{项目编号}-{作品名称}` 根目录，再套用同一棵可递归的目录树。管理员可以像文件资源管理器一样创建多级文件夹，把右侧统筹任务下的子文件任务拖入目录，并为每个文件任务单独配置命名规则。

示例规则：

- 按年度分目录
- 按组别分目录
- 按项目编号和作品名称生成项目文件夹
- 按材料类别归类
- 文件名包含项目编号、作品名称、负责人、材料名称

系统根据模板一键生成材料整理包，并记录归档导出记录。

### 对话 8：账号凭证立即失效机制

目标：解决账号删除、停用、修改密码或重置密码后，旧 JWT 仍能继续访问系统的问题。

- 为用户增加 `token_version`，写入 JWT，并在每次请求中查询数据库校验账号存在、未删除、已启用、角色和版本一致。
- 停用、删除、修改密码和重置密码时递增 `token_version`，让旧会话立即失效。
- 后端强制限制 `password_reset_required=1` 的用户只能访问本人信息、修改密码和退出接口。
- 增加退出接口；推荐将登录凭证迁移至生产环境启用 `Secure`、`HttpOnly`、`SameSite=Strict` 的 Cookie，前端不再把 JWT 存入 `localStorage`。

上线前仍需在目标 MySQL 备份后执行迁移 011；迁移会为现有正式项目负责人增加唯一索引，如果历史数据已有“一项目多负责人”或“一人负责多项目”，必须先清理冲突再应用。

### 加固完成后的总控验收

- 后端检查和前端正式构建通过。
- 前后端生产依赖安全审计不含高危漏洞。
- 被删除、停用或重置密码的账号旧会话立即失效。
- 不同项目负责人之间的材料、文件名和模板越权访问被拒绝。
- 归档任务能够排队、恢复、失败重试，并且自动测试不污染数据库和存储目录。
- 完成数据库与上传材料备份恢复演练、HTTPS、反向代理、防火墙、生产环境变量和磁盘告警检查后，才进入公网试运行。
