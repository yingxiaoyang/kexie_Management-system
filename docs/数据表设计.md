# 数据表设计

## 设计原则

现有 Excel 未在项目目录中发现原始文件。第一版按推进计划中已经确认的字段进行规范化拆表，不把负责人、成员、检查、报销和材料信息塞进一张大表。

数据库字符集：`utf8mb4`

数据库排序规则：`utf8mb4_0900_ai_ci`

时间口径：本地业务时间使用 Asia/Shanghai，接口统一返回 ISO 8601 字符串。

金额口径：数据库使用 `DECIMAL(12,2)`，接口返回字符串或两位小数，避免浮点误差。

## 核心表

### people 人员库

保存学生和指导老师。

关键字段：

- `person_type`：`student` / `teacher`
- `name`：姓名
- `student_no`：学号，学生唯一
- `teacher_no`：工号，老师唯一
- `college`：学院
- `unit`：单位
- `phone`、`qq`、`email`：联系方式
- `title`：职务或职称
- `account_status`：`none` / `enabled` / `disabled`

### users 账号表

保存登录账号。

关键字段：

- `username`：登录账号，唯一；新建学生账号固定为标准化后的学号，既有账号不批量改名
- `display_name`：显示名
- `password_hash`：加密后的密码
- `role`：`admin` / `applicant` / `project_owner`；开放注册固定创建 `applicant`，学校通过并成功转项目后升级为 `project_owner`
- `admin_level`：管理员层级，`super` / `limited`；非管理员为空
- `active_super_admin_slot`：生成列，唯一索引保证全库只有一个未删除超级管理员
- `status`：`enabled` / `disabled` / `locked`
- `person_id`：负责人账号可关联人员库
- `password_reset_required`：首次登录或重置后必须修改密码
- `token_version`：账号会话版本；停用、删除、修改密码、重置密码和退出时递增，使旧 JWT 立即失效
- `failed_login_attempts`：当前连续登录失败次数；登录成功或临时锁定期结束后的成功登录会清零
- `locked_until`：暴力尝试触发的临时锁定截止时间；到期后自动允许再次登录
- `last_failed_login_at`：最后一次密码验证失败时间

### admin_permission_definitions 后台权限定义

保存可扩展模块权限。当前键包括项目、人员、数据导入、材料任务、材料审核、立项申请、归档、报表和参与规则。`material_review` 独立保留，后续审核分发可复用该权限，本迁移不包含任务分发。

### admin_user_permissions 小管理员授权

以 `user_id + permission_key` 为主键，只允许给 `admin_level=limited` 的有效管理员授权。超级管理员不写授权明细，由服务层全权限绕过。

### admin_permission_audit_events 管理员权限审计

记录小管理员创建、权限变化、状态变化、密码重置和删除，保存操作人、目标账号、变更前后权限与时间；数据库触发器禁止更新和删除审计事件。

### projects 项目表

保存项目基础信息。

关键字段：

- `project_year`：项目所属年度
- `project_group`：组别
- `project_code`：项目编号，唯一
- `title`：作品名称
- `category`：项目类别
- `approval_date`：立项时间
- `approval_type`：`first` / `supplement`
- `status`：项目状态

### project_participations 项目参与关系

表达某个人在某个项目中的身份。

关键字段：

- `project_id`：项目
- `person_id`：人员
- `role`：`owner` / `member` / `advisor`
- `is_primary_owner`：是否主要负责人
- `joined_at`：加入时间

### participation_rules 参与规则

第一版默认：

- `max_owner_projects_per_person`：每人最多负责 1 个项目。
- `max_member_projects_per_person`：每人最多作为成员参与 2 个项目。

### project_check_records 检查记录

保存中期检查和阶段检查。

关键字段：

- `check_phase`：`midterm` / `stage`
- `research_log_count`：研究日志数量
- `rating`：评级
- `checked_at`：检查日期

### reimbursement_records 报销记录

保存项目报销额度和各阶段金额。

关键字段：

- `budget_amount`：报销额度
- `midterm_claim_amount`：中期申报金额
- `midterm_actual_amount`：中期实际金额
- `stage_claim_amount`：阶段申报金额
- `stage_actual_amount`：阶段实际金额
- `remaining_amount`：剩余额度

### material_tasks 统筹材料任务

管理员发布的统筹任务文件夹。一个统筹任务下包含多个单文件子任务。

关键字段：

- `task_name`：任务名称
- `project_scope_type`：`all` / `year` / `group` / `custom`
- `deadline_at`：截止时间
- `allowed_extensions`：允许文件类型
- `max_file_mb`：单文件大小限制
- `max_task_project_mb`：单项目单任务累计大小限制
- `has_template`：是否提供模板
- `status`：`draft` / `published` / `closed`

### task_template_attachments 材料任务模板附件

一个统筹任务可以有多个模板附件；迁移 004 后，模板附件可以明确关联到具体子文件任务。历史上没有子任务关联的公共模板继续兼容。

关键字段：

- `material_task_id`：材料任务
- `material_category_id`：对应子文件任务；为空时表示历史公共模板，通过 `004_file_task_rules_and_templates.sql` 新增
- `original_name`：原始文件名
- `storage_path`：本地存储路径
- `file_size`：文件大小
- `mime_type`：文件类型
- `uploaded_by`：上传管理员

### material_categories 子文件任务（兼容原材料类别表名）

统筹任务下的文件任务清单。为兼容已完成的提交、审核和外键关系，数据库表名及 `material_category_id` 外键名保持不变；新接口和页面把每条记录展示为“子文件任务”。

关键字段：

- `material_task_id`：材料任务
- `category_name`：子文件任务名称
- `task_description`：该子任务的提交说明，通过 `003_material_file_tasks.sql` 新增
- `allowed_extensions`：该子任务允许的提交文件扩展名 JSON，通过迁移 004 新增
- `max_file_mb`：该子任务单文件大小限制，通过迁移 004 新增
- `has_template`：该子任务是否向负责人提供模板，通过迁移 004 新增
- `is_required`：是否必交
- `sort_order`：排序

### material_submissions 材料提交记录

负责人提交材料后产生记录。

关键字段：

- `material_task_id`：材料任务
- `project_id`：项目
- `material_category_id`：材料类别
- `submitter_user_id`：提交人
- `submission_status`：`not_submitted` / `submitted` / `returned` / `overdue`
- `review_status`：`pending` / `approved` / `returned`
- `return_reason`：退回原因
- `submitted_at`、`reviewed_at`：提交和审核时间

### material_files 材料文件

新提交规则为一次提交只包含一个文件；历史多文件提交继续保留并可查看、审核和导出，因此数据表仍保持一对多结构。

关键字段：

- `submission_id`：提交记录
- `original_name`：原始文件名
- `storage_path`：本地存储路径
- `file_size`：文件大小
- `mime_type`：文件类型

### archive_templates 归档模板

保存可视化归档模板配置。

关键字段：

- `template_name`：模板名称
- `template_config`：版本化的项目根目录、递归目录树、子任务放置位置、文件命名规则和空目录保留选项 JSON
- `status`：启用状态

### archive_export_records 归档导出记录

保存材料整理包导出历史。

关键字段：

- `export_user_id`：导出人
- `archive_template_id`：使用的模板
- `export_scope`：导出范围 JSON
- `template_snapshot`：创建导出时保存的模板配置快照，避免模板后续编辑影响历史记录
- `export_file_path`：导出包路径
- `export_summary`：应收材料、通过材料、导出文件、缺失条目和文件大小统计 JSON
- `export_status`：`queued` / `processing` / `success` / `failed`
- `attempt_count`：当前已尝试次数
- `max_attempts`：最大尝试次数
- `started_at`：Worker 最近一次开始处理时间
- `heartbeat_at`：Worker 心跳时间，用于重启或卡死恢复
- `worker_id`：处理该任务的 Worker 标识
- `failure_reason`：失败原因；成功时为空
- `created_at`、`finished_at`：任务创建和完成时间
- `zip_cleanup_at`：ZIP 文件按保存期限自动清理的时间；记录仍保留

### import_batches 导入批次记录

永久保存正式导入、简化导入预检查和回滚追加记录。

关键字段：

- `batch_uuid`：对外展示和接口使用的批次编号。
- `import_type`：`standard_workbook` / `simple_projects` / `project_field_update` / `people_update` / `project_participations` / `check_record_update` / `reimbursement_update` / `rollback`。
- `mode`：导入模式，简化导入默认 `upsert`，回滚记录为 `revert`。
- `status`：`validated` / `committed` / `failed` / `rolled_back` / `rollback_partial`。
- `original_file_name`、`original_file_path`：原始上传文件名和长期保存路径。
- `file_sha256`、`file_size`：原始文件校验值和大小。
- `summary_json`、`errors_json`：预检查、正式导入和回滚统计及错误清单。
- `parent_batch_id`：回滚记录指向原导入批次。
- `created_by`、`committed_by`、`rolled_back_by`：操作管理员。
- `created_at`、`committed_at`、`rolled_back_at`：关键时间。

### import_batch_records 导入逐行记录

按记录保存每一行导入或回滚动作。

关键字段：

- `batch_id`：所属导入批次。
- `entity_type`：`project` / `person` / `participation` / `check_record` / `reimbursement` / `rollback`。
- `entity_key`：业务唯一识别，例如项目编号或 `项目编号 + 人员编号 + 身份`。
- `target_table`、`target_id`：影响的数据表和主键。
- `operation_type`：`create` / `update` / `remove` / `skip` / `error` / `restore` / `conflict`。
- `excel_row_number`：来源 Excel 行号。
- `status`：`planned` / `applied` / `skipped` / `failed` / `conflict`。
- `before_snapshot`、`after_snapshot`：修改前后必要快照。
- `message`：跳过、冲突或兼容导入说明。

### import_batch_field_changes 导入字段差异

按字段保存“原值到新值”的差异，供详情页和差异导出使用。

关键字段：

- `record_id`：所属逐行记录。
- `field_name`：字段名。
- `before_value`：修改前值。
- `after_value`：修改后值。

归档导出扩展字段通过 `database\migrations\002_archive_export_audit.sql` 加入；子文件任务说明字段通过 `database\migrations\003_material_file_tasks.sql` 加入；子任务独立格式、大小、模板开关以及模板附件的子任务关联通过 `database\migrations\004_file_task_rules_and_templates.sql` 加入；账号会话版本通过 `database\migrations\005_user_token_version.sql` 加入；登录失败计数、临时锁定和最后失败时间通过 `database\migrations\006_user_login_protection.sql` 加入；归档导出队列字段和 `queued` 状态通过 `database\migrations\007_archive_export_queue.sql` 加入；项目数据报表设计器通过 `database\migrations\008_report_designs_and_exports.sql` 加入；导入批次、逐行记录、字段差异和回滚追加记录通过 `database\migrations\009_import_batches_and_reverts.sql` 加入；人员、检查和报销动态导入类型通过 `database\migrations\010_expand_dynamic_import_modules.sql` 加入；立项申请与审批闭环通过 `database\migrations\011_application_approval_loop.sql` 加入；学生账号与管理员权限通过 `database\migrations\012_admin_permissions_and_student_accounts.sql` 加入。以上调整都没有修改已经用于初始化的 `001_init.sql`。数据库初始化命令会通过 `schema_migrations` 表按文件名顺序执行尚未应用的迁移。

## 立项申请与审批闭环（迁移 011）

立项申请使用独立领域表，不复用正式项目后续的 `material_tasks` / `material_submissions`，从数据语义上区分“校内材料合格性审核”和“学校正式立项结果”。

- `application_batches`：首次/补充立项批次、开放截止时间、动态字段和状态。
- `application_material_requirements`：必交材料、扩展名、大小、模板和 SHA-256。
- `project_applications`：申请归属、状态机、提交版本、材料审核、学校结果和正式项目关联。
- `application_material_files`：不可变文件版本；同一材料每次上传新增行。
- `application_material_reviews`：按申请提交版本保存材料合格/退回、审核人、时间和意见。
- `application_export_records` / `application_export_items`：冻结报送批次、数据快照、学校 Excel、材料包和撤回原因。
- `school_result_imports`：学校反馈文件或逐条录入的持久记录、预检查结果、标准化数据和 SHA-256；`storage_path` 可空，无效预检查文件删除临时实体后仅保留元数据与错误摘要，合法和已提交凭据保留。
- `project_approval_sources`：正式项目追溯到申请、批次、学校名单；历史缺失材料明确标记 `missing_historical`。
- `application_audit_events`：不可变审计事件；数据库触发器禁止更新和删除。

迁移同时把 `users.role` 扩展为 `applicant`，并给 `project_participations` 增加“每项目唯一负责人、每学生最多负责一项目”的生成列唯一索引。`project_applications` 使用生成列唯一索引保证一个学生同一时间只有一份进行中申请。

负责人完整性由索引与事务服务共同保证：`draft` 可暂时没有负责人；`active`、`checking`、`completed`、`archived`、`stopped` 提交时必须恰好一名未删除学生负责人。011 执行前由初始化器预查多负责人、负责人重复、正式项目无负责人并中止冲突迁移，不生成虚假负责人。
