# 后端运行说明

## 项目位置

后端基础服务位于：

```text
D:\kexiexitong\server
```

数据库迁移脚本位于：

```text
D:\kexiexitong\database\migrations
```

`npm.cmd run db:init` 会创建 `schema_migrations` 记录表，并依次执行尚未应用的迁移。账号会话版本字段使用 `005_user_token_version.sql`，登录失败和临时锁定字段使用 `006_user_login_protection.sql`；已经记录的迁移不会重复执行。

## 运行前准备

本任务不负责 Docker 安装。运行后端前，需要先确认：

- Docker Desktop 已启动。
- MySQL 容器 `kexie-mysql` 已运行。
- 数据库名为 `kexie_db`。
- 应用用户为 `kexie_user`。
- 数据库密码从 `D:\kexiexitong\database\.env.mysql` 读取。

## 启动步骤

```powershell
cd D:\kexiexitong\server
Copy-Item .\.env.example .\.env
npm.cmd install
npm.cmd run db:init
npm.cmd run dev
```

`server\.env` 至少需要修改：

```text
DB_PASSWORD=<database\.env.mysql 中的 MYSQL_PASSWORD>
JWT_SECRET=<较长随机字符串>
INITIAL_ADMIN_PASSWORD=<管理员初始密码>
```

登录保护与代理配置默认值：

```text
TRUST_PROXY=false
REQUEST_BODY_LIMIT=256kb
LOGIN_RATE_LIMIT_WINDOW_MINUTES=15
LOGIN_RATE_LIMIT_MAX=20
ADMIN_LOGIN_RATE_LIMIT_MAX=10
ACCOUNT_LOCK_MINUTES=15
ADMIN_ACCOUNT_LOCK_MINUTES=30
```

本地直接访问保持 `TRUST_PROXY=false`。生产环境由同机 Nginx/Caddy 反向代理时建议使用 `TRUST_PROXY=loopback`，让限流读取真实客户端 IP；生产环境禁止使用会信任任意转发链的 `TRUST_PROXY=true`。

登录凭证使用 `kexie_session` HttpOnly Cookie。开发环境允许 HTTP；`NODE_ENV=production` 时自动增加 `Secure`，并始终使用 `SameSite=Strict` 与 `/api` 路径。Cookie 名可通过 `AUTH_COOKIE_NAME` 调整。

生产启动会检查安全配置。JWT 密钥、数据库密码、初始管理员密码仍为示例值或长度不足，CORS 使用 `*`、`null`、HTTP、本机开发地址，或代理信任过宽时，服务会直接拒绝启动。生产 `CORS_ORIGINS` 必须填写无路径、无尾斜杠的精确 HTTPS Origin，例如 `https://portal.example.edu.cn`。

登录连续失败 5 次会触发账号临时锁定；负责人默认 15 分钟，管理员默认 30 分钟。登录成功会清空失败次数、锁定截止时间和最后失败时间。Helmet、Origin 检查和 `256kb` 请求体限制在所有接口前统一执行；文件上传继续由各上传接口的 Multer 限制控制。

认证中间件会在每次受保护请求中查询 `users` 表，核对账号存在、未软删除、状态为启用、角色和 `token_version` 与 JWT 一致。账号停用、删除、改密、重置和退出后，旧会话立即失效。

## 本地文件存储

默认上传目录：

```text
D:\kexiexitong\storage\uploads
```

该目录属于本地运行数据，不提交 GitHub。

默认整理包导出目录：

```text
D:\kexiexitong\storage\exports
```

可在 `server\.env` 中通过下列变量调整：

```text
UPLOAD_ROOT=../storage/uploads
EXPORT_ROOT=../storage/exports
```

归档下载接口只允许管理员访问，并会验证下载文件仍位于 `EXPORT_ROOT` 内。

## 归档导出检查

后端语法与模块检查：

```powershell
cd D:\kexiexitong\server
npm.cmd run check
```

账号会话真实闭环检查：

```powershell
npm.cmd run check:auth
```

登录保护与生产配置真实闭环检查：

```powershell
npm.cmd run check:security
```

该检查会创建临时账号，并在 `finally` 中删除，覆盖正常登录、错误密码、连续 5 次锁定、自动解锁、成功清零、普通/管理员 IP 限流、代理 IP、Helmet、Origin、请求体上限、日志脱敏和生产启动拒绝规则。

该检查会创建临时账号并在 `finally` 中清理，覆盖首次改密接口限制、改密、退出、停用、重置、删除和角色变化后的旧会话失效。

在后端服务已启动的情况下，可运行真实归档闭环检查：

```powershell
npm.cmd run check:archive
npm.cmd run check:archive-tree
```

该检查会验证：

- 归档模板真实接口。
- 审核通过材料 ZIP 生成与管理员下载。
- 无审核通过材料时生成真正的 Excel 文件 `缺失材料报告.xlsx`，并包含负责人电话。
- ZIP 根目录的 `导出材料清单.xlsx` 也是 Excel 文件，并包含负责人电话。
- 项目负责人不能访问管理员归档接口。
- 导出目录外的下载路径会被拒绝。
- Windows 非法字符、路径穿越和重名序号处理。

`check:archive` 创建的测试导出记录与 ZIP 会在检查结束后自动清理；临时创建的缺失材料任务也会删除。

`check:archive-tree` 额外验证：

- 版本 2 模板真实新建和示例目录树预览。
- 统筹任务与子文件任务库接口。
- 每个项目一个根目录、多级文件夹和子任务文件命名。
- `preserveEmptyFolders` 配置和版本 2 ZIP 生成。

目录树检查产生的临时模板、导出记录和 ZIP 会在检查结束后自动清理。

`check:archive-queue` 额外验证：

- 导出任务先进入 `queued` 队列。
- Worker 串行认领任务并生成 ZIP。
- 失败任务达到最大尝试次数后标记失败，并可由管理员重试。
- Worker 心跳超时后自动恢复任务。
- 过期 ZIP、旧临时 ZIP 和过期导入预检批次自动清理。

## 归档导出队列

归档导出已改为数据库队列。开发环境默认随后端一起启动一个归档 Worker；生产环境可设置 `ARCHIVE_WORKER_ENABLED=false`，再用独立进程运行：

```powershell
cd D:\kexiexitong\server
npm.cmd run worker:archive
```

常用队列与存储限制可在 `server\.env` 调整：

```text
ARCHIVE_EXPORT_MAX_ATTEMPTS=3
ARCHIVE_EXPORT_MAX_QUEUED=5
ARCHIVE_EXPORT_MAX_PROJECTS=300
ARCHIVE_EXPORT_MAX_TOTAL_MB=2048
ARCHIVE_EXPORT_MIN_FREE_MB=1024
ARCHIVE_ZIP_RETENTION_DAYS=30
IMPORT_BATCH_RETENTION_HOURS=24
```

Worker 会恢复心跳超时的 `processing` 任务，未超过最大尝试次数时重新排队，达到上限后标记失败。过期 ZIP、旧 `.tmp` 文件和过期导入预检批次会由清理任务自动移除，历史导出记录继续保留。

## 子文件任务独立规则

迁移 `004_file_task_rules_and_templates.sql` 为每个子文件任务增加独立的允许格式、单文件大小和模板开关，并让模板附件可以关联到具体子任务。应用方式：

```powershell
cd D:\kexiexitong\server
npm.cmd run db:init
```

管理员材料任务接口支持全部项目、指定年度、指定组别和指定项目四种范围。已发布但尚无提交的任务仍可修改；收到任何提交后，或者任务处于关闭状态时，后端会拒绝修改以保护历史记录。

## 单文件提交约定

负责人提交接口 `POST /api/uploads/submissions` 使用 `multipart/form-data`，文件字段名为 `file`，一次请求必须且只能上传一个文件。退回后重新上传会新增提交版本；旧的提交记录和历史多文件数据不会被覆盖。
