## A. 跨届黑名单

### 数据与规则

- `participation_restrictions` 保存限制事实，`participation_restriction_events` 保存不可变审计事件。
- 原因分为 `missing_required_material` 与 `project_terminated`，同一人员的不同原因独立存在。
- 限制年度固定为来源项目年度加一；资格查询只匹配目标项目年度，所以下下一届自动恢复。
- 受限账号仍可登录并查看历史；限制只拦截申请人、负责人、成员资格，不处理指导教师。
- 缺材料限制在该任务全部必填材料出现审核通过版本后自动解除；项目终止限制不会被补材料解除。
- `INSERT IGNORE + 来源/人员/年度唯一键` 保证扫描幂等；旧 `stopped` 状态与新 `terminated` 状态均按终止处理。

### 业务接入

统一服务：`server/src/services/participationEligibilityService.js`。

- 自主立项：创建、编辑、提交时检查申请人，以及申请数据中的 `memberPersonIds` / `memberStudentNos`（同时兼容下划线键和中文键）。
- 项目管理：新增负责人、维护成员时检查目标项目年度。
- 项目变更审批：负责人转移和新增成员在审批生效事务内检查。
- 批量导入：计划导入和标准工作簿在正式写入事务内检查；学校结果/历史名单转正式项目也检查。
- 材料任务发布/关闭且已逾期时同步扫描；材料审核通过时同步尝试解除缺材料限制。
- 项目状态首次进入 `terminated` 或兼容状态 `stopped` 时同步触发。
- 定时/人工全量扫描同时补齐逾期缺材料和历史终止项目，重复运行不重复写入。

### API 与权限

- `GET /api/participation-rules/restrictions`：活动/历史筛选；小管理员需要 `participation_rules`。
- `GET /api/participation-rules/restrictions/export`：按当前筛选导出 UTF-8 CSV，已防公式注入。
- `GET /api/participation-rules/restrictions/:id/events`：限制审计时间线。
- `POST /api/participation-rules/restrictions/scan`：超级管理员人工幂等扫描。
- `PATCH /api/participation-rules/restrictions/:id/status`：超级管理员凭必填书面原因解除/恢复。
- 定时入口：在 `server` 目录执行 `npm run scan:participation-restrictions`。建议由单实例计划任务调用；数据库唯一键保证多次执行安全。

管理页将活动限制、历史记录、数量规则分开展示；项目工作台显示当前限制年度与原因，触发/解除/恢复也进入项目时间轴。

## B. 归档与整理包导出

### 模板兼容

- V2 材料节点新增 `requiredMode`：`inherit`、`required`、`optional`。
- 新节点默认继承材料子任务的 `is_required`；模板可明确覆盖。
- 旧节点缺少该字段时规范化为继承，并返回 `requiredReviewNeeded=true`，编辑器直观提示核对。
- 旧版平铺模板继续兼容；可确定任务必填性时继承任务，不能由旧节点覆盖。

### 规则矩阵

| 适用性 | 必填性 | 最新状态 | 正式目录 | 报告 |
|---|---|---|---|---|
| 不适用 | 任意 | 任意 | 不进入 | 材料适用性明细，原因“任务未实际发布给该项目” |
| 适用 | 必填 | 未提交/待审/退回 | 不进入 | 缺失材料报告 |
| 适用 | 选填 | 从未提交 | 不进入 | 只记明细，正常跳过 |
| 适用 | 选填 | 待审/退回 | 不进入 | 选填材料状态报告 |
| 适用 | 任意 | 最新提交审核通过 | 进入 | 导出清单与适用性明细 |

任务适用性按 `all/year/group/custom` 的实际发布范围计算。正式文件只取当前最新提交且审核通过的版本；若最新版本待审或退回，不回退导出旧通过版本。关闭“保留空文件夹”时，选填未提交不会创建目录。

整理包固定生成 `导出材料清单.xlsx`、`材料适用性明细.xlsx`、`导出说明.txt`；按情况生成 `缺失材料报告.xlsx`、`选填材料状态报告.xlsx`。Excel/CSV 输出统一防 `= + - @` 公式注入并保留中文。

### 预检、快照与快捷导出

- `POST /api/archive-exports/preflight` 返回：项目数、适用任务数、正式材料数、必填缺失/待审/退回数、选填未提交数、选填异常数、不适用数，以及固化后的 `scopeSnapshot`。
- `POST /api/archive-exports` 仍使用原导出队列，并保存项目 ID 快照与筛选条件；`snapshotLocked=true` 后不会在入队时重新解析列表。
- 整理包页面年度、组别来自真实项目数据，均为动态多选，并提供全选。
- 项目管理列表实现“导出所选项目”和“导出当前筛选全部项目”；后者在预检时展开为精确项目 ID 快照。
- 所有快捷入口最终调用 `archive_management` 后端路由；无权限用户前端不显示，直接调用仍由后端拒绝。

## 已知限制

- 系统目前没有独立的“立项申请成员”关系表；申请成员资格依赖批次表单使用约定字段 `memberPersonIds`、`memberStudentNos`、`member_person_ids`、`member_student_nos`、`成员人员ID` 或 `成员学号`。正式项目成员关系与项目变更成员不受此限制。
- 旧状态 `stopped` 为兼容历史继续保留；新业务页面使用 `terminated`。全量扫描会为两种状态补齐限制。
- 导出仍受现有项目数、总文件大小、磁盘余量和队列长度上限约束。
- 生产定时调度由部署环境配置；代码提供幂等命令，不在应用进程内隐式创建系统计划任务。
