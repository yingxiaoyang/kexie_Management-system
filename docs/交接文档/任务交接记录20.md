## 完成内容

- 材料任务增加“项目信息变更”类型，管理员发布时必须选择中期/阶段检查，并配置允许变更项目成员、指导教师、项目负责人中的至少一类。任务类型创建后不可切换。
- 特殊任务必须走 `/api/project-changes` 结构化流程；普通单文件上传接口会拒绝该类型，防止材料版本和变更方案脱节。
- 负责人可保存草稿、上传证明、正式提交；成员和导师支持增删，负责人交接支持原负责人转普通成员或退出。退回后沿用同一申请修改并生成新版本重提。
- 正式提交时才创建 `material_submissions` 版本；当时的前快照、结构化方案、提交人和证明文件与该提交 ID 一一绑定并冻结。版本表和审计表禁止 UPDATE/DELETE。
- 审核继续使用 014 的 `assigned_to`、`assignment_version` 和 `material_review` 边界。小管理员只能查看文件、对比和审核分给自己的变更材料，超级管理员可以查看全部和处理未分配项。
- 审核通过在一个事务内重新锁定并校验项目、当前负责人、候选人账号和候选人的其他负责人关系，然后一次性更新成员/导师/负责人关系、账号角色和审计；退回不修改项目关系或原负责人权限。
- 超级管理员可以在现负责人无法操作时强制发起负责人变更，但必须填写原因、上传依据并形成正常待审版本；接口不提供无痕直接改负责人。
- 管理端支持待审核、已通过、已退回筛选和 Excel 导出，字段包含项目、任务、申请人、发起方式、变更摘要、状态、版本、提交/审核人和时间。该导出不是归档整理包。
- 项目工作台时间轴显示变更提交、退回和审批生效；生效节点保存前后快照。历史材料仍按项目归属，新负责人通过当前 owner 关系取得访问，旧负责人不再拥有项目访问。

## 状态机与版本

`draft -> submitted -> returned -> submitted -> approved`

- `draft`：结构化方案可修改，可追加证明文件，不产生待审材料。
- `submitted`：生成新的材料提交和不可变 `project_change_versions`；待审期间项目关系不变。
- `returned`：保存审核人、原因和不可变退回事件；允许修改后重提，版本号加一。
- `approved`：终态；同一事务内应用关系和账号变化，保存生效时间与前后快照。
- 当前申请用 `latest_submission_id + current_version` 指向唯一待审版本。旧版本审批、重复审批、改派后的旧页面提交均返回中文 409 冲突。

## 负责人资格和账号转换

统一入口为 `assertProjectOwnerCandidateQualified`，后续黑名单规则只能追加到该入口，不能散落到路由。本次没有实现黑名单。

- 候选人必须是未删除学生，人员和账号均未禁用，账号用户名必须等于学号。
- 候选人必须已自行注册；无账号返回 `PROJECT_OWNER_REGISTRATION_REQUIRED`，管理员不会替申请人创建账号。
- 候选账号允许从 `applicant` 升级为 `project_owner`，也允许复用当前没有负责项目的 `project_owner` 账号。
- 候选人不能同时负责其他未删除正式项目；提交时预检，审批生效时在锁内再次校验。
- 新负责人账号切换为 `project_owner` 并递增 `token_version`。原负责人若不再负责其他项目，安全降级为现有模型支持的 `applicant` 并递增 `token_version`，保留登录与历史立项申请访问。
- 审批事务结束前断言项目恰有一个 active owner；数据库 011 的唯一索引继续作为最终防线。

## 权限和并发边界

| 操作 | 当前负责人 | 有 `material_review` 小管理员 | 超级管理员 |
| --- | --- | --- | --- |
| 查看项目 | 仅当前 owner，只读 | 按既有项目权限 | 全部 |
| 创建普通变更 | 可以 | 不可以 | 不代替负责人 |
| 强制负责人变更 | 不适用 | 不可以 | 可以，必须原因和依据 |
| 查看/审核变更材料 | 自己发起的版本 | 仅本人受派版本 | 全部 |
| 分配/改派审核 | 不可以 | 不可以 | 复用 014 批量分配 |
| 直接改负责人 | 不可以 | 不可以 | 不可以，必须审批 |

并发保护包括：材料行锁、申请行锁、分配版本条件更新、最新提交与变更版本一一绑定、待审基线关系指纹校验、候选人行锁和负责人关系唯一索引。重复审批、旧版本审批、待审期间人员关系漂移、候选人同时成为其他项目负责人都会回滚并返回中文冲突。

## 主要 API

- `GET /api/project-changes/options`：适用的中期/阶段变更任务、项目和人员候选项。
- `GET /api/project-changes`：负责人自己的申请；管理员按受派范围和状态筛选。
- `POST /api/project-changes`：负责人建草稿，或超级管理员带 `forcedReason` 强制发起。
- `PUT /api/project-changes/:id`：草稿/退回版本修改结构化方案。
- `POST /api/project-changes/:id/proof`：上传证明或强制变更依据。
- `POST /api/project-changes/:id/submit`：冻结方案、快照和证明并创建材料版本。
- `GET /api/project-changes/:id`：证明、版本、冻结前快照和当前快照。
- `GET /api/project-changes/export`：按状态导出结构化 Excel。
- `PATCH /api/submissions/:id/review`：沿用 014 审核入口；特殊任务通过时调用项目变更事务。
