# 科研项目管理平台任务交接记录

## 2026-08-19：学生账号统一学号与多管理员模块权限

## 当前结论

本次以主线提交 `b950e35`、既有迁移 `011` 为基线，新增 `012_admin_permissions_and_student_accounts.sql`，完成学生账号规则、已有人员安全复用、唯一超级管理员、小管理员模块授权、前后端权限一致和权限审计。没有修改或清空实际测试数据库，没有推送远程。

保留 `admin`、`applicant`、`project_owner` 三个既有角色；管理员层级通过 `users.admin_level=super|limited` 表达，避免破坏原有登录跳转、负责人门户和立项申请流程。

## 账号规则

- 申请人注册不再接收独立用户名。后端将学号 `trim + uppercase` 后强制作为 `username`，前端登录提示改为“账号/学号”。
- 管理员新建项目负责人账号时只选择已有 student 人员，后端读取并标准化其学号作为用户名，不信任前端自填用户名。
- 已存在 student 人员但没有账号、也没有 owner 关系时，申请人注册在姓名一致后复用该人员，只补空的学院/电话/邮箱，不重复创建人员；姓名不一致或记录已归档时要求管理员核实。
- 已绑定账号返回 `PERSON_ACCOUNT_ALREADY_BOUND`；学号已注册返回 `STUDENT_NUMBER_REGISTERED`；已是项目负责人时申请人注册返回 `STUDENT_ALREADY_PROJECT_OWNER`。
- 既有用户不批量修改 `username`，仍按原账号登录；申请人转正式负责人只是原账号角色升级，不会改名。

## 管理员与权限

- 迁移将现有有效管理员中优先用户名为 `admin`、否则 ID 最小者设为唯一超级管理员；其他旧管理员变为小管理员并一次性继承全部现有业务模块权限，保证升级兼容。
- 新装数据库先执行迁移，再由 `init-db` 创建唯一超级管理员；若已有超级管理员，不会按环境变量再创建第二个。
- `users.active_super_admin_slot` 生成列唯一索引阻止第二个未删除超级管理员；触发器阻止停用、删除或降级唯一超级管理员。
- 服务层只允许超级管理员访问 `/api/accounts`，新建管理员固定为 `limited`；小管理员不能查看或调用管理员管理、重置、删除和授权接口。
- 权限目录覆盖 `project_management`、`people_management`、`data_import`、`material_task`、`material_review`、`application_management`、`archive_management`、`report_management`、`participation_rules`。
- 所有现有后台业务 API 已接入模块权限中间件；项目负责人和申请人仍使用原角色与数据归属校验。
- `material_review` 独立保留，当前只控制材料查看/审核；未实现后续审核任务分发。
- 新增 `admin_permission_audit_events`，记录小管理员创建、权限变化、状态变化、密码重置和删除；数据库触发器禁止修改或删除。

## 未完成与风险

- 012 已通过一次性临时 MySQL 8.4 全量迁移验证；上线时仍必须先备份目标库，再执行 `db:init`，不要跳过既有 011 迁移前置检查。
- 权限变更会递增目标小管理员 `token_version`，旧会话立即失效；管理员需要重新登录，这是预期行为。
- 旧的非初始化管理员升级后默认继承全部业务模块，建议上线后由超级管理员按最小权限重新收敛。
- 若历史库中初始化管理员已被软删除且其用户名仍占用，`init-db` 会拒绝悄悄复活或覆盖该账号；需先由运维核实历史记录，再决定恢复或更换 `INITIAL_ADMIN_USERNAME`。
- 前端生产构建仍有既有主包超过 500 kB 的性能警告，不影响本任务功能；后续可做组件级拆包。
- `material_review` 只完成权限边界，没有实现审核人员分发、领取、转派或工作量表。
