## 2026-08-06：对话 7 - 归档模板、统筹任务与材料整理包导出

## 当前结论

对话 7 已完成，并按使用方确认后的实际工作方式进行了二次增强：一个归档模板适用于所有项目，每个项目在 ZIP 中拥有自己的根文件夹；管理员先建立统筹任务，再建立多个一次只接收一个文件的子任务，并在资源管理器式模板编辑器中把子任务放入任意多级目录。

没有撤销或重写对话 4、5、6 已有的登录、材料审核、负责人门户和管理员布局。旧版归档模板、历史提交和历史导出快照继续兼容。

## 业务模型

- `material_tasks`：统筹任务文件夹，例如“2026 年结项材料”。
- `material_categories`：继续使用原表和外键，但新页面和接口将每条记录解释为子文件任务，例如“项目申报书”“中期检查报告”。
- 每个项目、每个子文件任务、每次提交只允许一个文件。
- 被退回后可以重新提交；每次重交新增一个提交版本，历史记录不覆盖。
- 历史上已经存在的多文件提交继续可查看、审核和导出。

## 归档模板配置结构

新模板使用版本 2：

```json
{
  "version": 2,
  "projectRootRule": "{项目编号}-{作品名称}",
  "preserveEmptyFolders": false,
  "defaultFileNameRule": "{材料类别}_{原文件名}",
  "nodes": [
    {
      "id": "folder-1",
      "type": "folder",
      "nameRule": "01-立项材料",
      "children": [
        {
          "id": "folder-2",
          "type": "folder",
          "nameRule": "申报文件",
          "children": [
            {
              "id": "task-1",
              "type": "task",
              "materialTaskId": 3,
              "fileTaskId": 12,
              "materialTaskName": "2026 年结项材料",
              "fileTaskName": "项目申报书",
              "fileNameRule": "{项目编号}_{材料类别}_{原文件名}"
            }
          ]
        }
      ]
    }
  ]
}
```

规则说明：

- `projectRootRule`：每个项目的根文件夹命名规则。
- `nodes`：递归目录树；`folder` 可包含文件夹和任务，最多 8 层、总节点最多 300 个。
- `task`：放入模板的真实子文件任务，并可配置自己的 `fileNameRule`。
- 同一子文件任务在一个模板中只允许出现一次。
- `preserveEmptyFolders`：是否把模板中的空目录写入 ZIP。
- 支持年度、组别、项目编号、作品名称、负责人、材料任务、材料类别、原文件名占位字段。
- 旧版 `version: 1` 平铺模板仍可直接导出；编辑旧模板时前端提示转换为版本 2 并重新放置子任务。

## 缺失材料处理

- 每个已放入模板的子文件任务只选择最新一次审核通过版本。
- 更晚的待审核或退回版本不会覆盖已有审核通过版本。
- 待审核、退回、未提交材料不进入正式材料目录。
- 没有任何审核通过版本时，写入 `缺失材料报告.csv`，并注明“未提交”“待审核”或“已退回”。
- 审核通过版本没有关联文件、文件丢失或路径不在系统上传目录时，同样进入缺失报告。
- 筛选范围没有任何匹配材料时，也会生成一条明确报告，不会返回没有说明的空 ZIP。
