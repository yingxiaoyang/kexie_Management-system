## 归档模板配置结构

```json
{
  "version": 1,
  "directoryLevels": [
    { "pattern": "{年度}年" },
    { "pattern": "{组别}" },
    { "pattern": "{项目编号}-{作品名称}" },
    { "pattern": "{材料任务}" },
    { "pattern": "{材料类别}" }
  ],
  "fileNameRule": "{项目编号}_{作品名称}_{负责人}_{材料类别}_{原文件名}"
}
```

## 后续需要知道

- `EXPORT_ROOT` 默认是 `D:\kexiexitong\storage\exports`，属于本地运行数据，不提交 Git。
- 导出任务在当前 Node 进程内异步执行；第一版单机试用足够。正式多实例部署时建议改为持久化任务队列，并为长时间停留在 `processing` 的任务增加恢复机制。
- ZIP 依赖 `archiver`。本次安装时 npm 报告依赖树存在 1 个 high severity 安全项；正式公网部署前需要结合 `npm audit` 复核并安排依赖升级，不能仅凭自动修复盲目升级业务依赖。
- 自动检查会保留导出记录和 ZIP 供人工查看，临时缺失材料任务会自动删除。
