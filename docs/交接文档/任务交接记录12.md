# 科研项目材料管理平台任务交接记录

## 2026-08-07：对话 12 - 可靠的归档导出任务队列

## 当前结论

对话 12 已完成。归档导出现在由数据库队列驱动：接口只创建 `queued` 任务并立即返回，归档 Worker 串行处理 ZIP 生成。Worker 重启后会恢复心跳超时的任务，未超过最大尝试次数时重新排队，达到上限后标记失败；管理员可在前端对失败任务执行重试。

## 已完成

- 新增迁移 `database\migrations\007_archive_export_queue.sql`：
  - `export_status` 扩展为 `queued` / `processing` / `success` / `failed`。
  - 增加 `attempt_count`、`max_attempts`、`started_at`、`heartbeat_at`、`worker_id`、`zip_cleanup_at` 和队列/清理索引。
- 后端新增归档队列服务：
  - 创建任务前限制同时排队数量、单次导出项目数、源文件总量，并检查导出目录磁盘空间。
  - Worker 使用数据库锁确保第一版同一时间只执行一个大型导出。
  - 处理过程中写入心跳；超时任务可自动恢复。
  - 失败未达上限自动回到队列，达到上限后保留失败原因。
  - 过期 ZIP、旧 `.tmp` 文件和过期导入预检批次会自动清理，历史导出记录保留。
- 后端接口保持兼容：
  - `POST /api/archive-exports` 返回 `queued`。
  - 列表和详情继续返回原有统计字段，并新增尝试次数、心跳和 Worker 信息。
  - 新增 `POST /api/archive-exports/:id/retry`。
  - 下载接口继续只允许管理员，并保持 `EXPORT_ROOT` 真实路径校验。
- 前端整理包导出页已显示“排队中”、尝试次数、ZIP 已清理状态，并为失败任务提供“重试”按钮。
- 修复 `check-archive-flow.js`：
  - 校验导出任务先进入 `queued`。
  - 轮询兼容 `queued` 和 `processing`。
  - 测试导出记录和 ZIP 在 `finally` 中自动删除。

## 运行说明

开发环境默认随后端启动归档 Worker：

```powershell
cd D:\kexiexitong\server
npm.cmd run start
```

如生产环境希望 API 与 Worker 分离，可在 API 进程设置：

```text
ARCHIVE_WORKER_ENABLED=false
```

再单独运行：

```powershell
npm.cmd run worker:archive
```
