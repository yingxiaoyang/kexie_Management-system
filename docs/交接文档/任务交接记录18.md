## 完成内容

- 管理员项目列表增加组别/类别筛选、团队和材料概览、预留多选列；项目行进入独立全页工作台，不再用超长弹窗编辑既有项目。
- 负责人“我的项目”进入相同 `ProjectWorkspace.vue`，共享项目摘要、生命周期、详情、团队、材料全部版本和时间轴；页面标识只读。
- 后端 `projectWorkspaceService.js` 统一组装两个角色的数据。负责人按当前账号 `person_id + owner` 有效关系校验，只能读取自己的项目；管理员必须有 `project_management`。
- 项目字段采用分区表单编辑，记录逐字段 `{field,before,after}`。普通编辑接口不补建、不移除、不替换负责人。
- 管理员可整体维护成员和指导教师；成员限定学生、导师限定教师，每次写入完整关系前后快照，owner 原样保留。
- 材料按统筹任务/子任务展示所有提交版本、文件、提交人/时间、审核状态、退回原因、审核人/时间；文件下载同时做项目归属和存储根路径校验。
- 时间轴聚合项目审计、立项审计/来源、永久导入记录、材料提交和材料审核事实，区分已完成、当前、异常/退回并支持事件类别筛选。
- 旧项目没有某类专用事件时，仅从 `created_at`、真实来源关系、导入/提交/审核记录生成 `legacyDerived=true` 节点；缺失操作者保持 `null`。

## 字段与事件模型

迁移 `013_project_workspace_audit.sql`：

- `projects.approval_batch VARCHAR(160) NULL`：兼容旧项目手工批次；在线申请来源优先显示真实 `application_batches.batch_name`，迁移不回填旧值。
- 新表 `project_audit_events`：`project_id`、`event_type`、`actor_user_id`、`source_module`、`field_changes JSON`、`event_payload JSON`、`created_at`。
- `project_audit_events` 有禁止 UPDATE/DELETE 的触发器；迁移 011 的 `uk_one_owner_per_project` 与 `uk_one_project_per_owner` 不变。

时间轴类别为 `project/application/participation/material/import`，展示状态为 `completed/current/exception`。材料版本号由现有 `material_submissions` 历史顺序派生，不修改现有材料版本模型。
