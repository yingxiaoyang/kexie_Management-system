# 科研项目管理平台任务交接记录

## 2026-08-19：申请人自主注册与立项审批闭环（集成修正版）

## 当前结论

本次在既有 Vue 3 + Element Plus、Node/Express、MySQL 迁移架构中新增独立立项域，完成从申请人自主注册、补充立项申请、材料合格性审核、冻结报送、学校结果，到正式项目和唯一负责人建立的闭环。没有修改 `001_init.sql`，现有 admin/project_owner 的项目、后续材料、导入、归档和报表路由保留。

特别说明：管理员审核文案和审计含义均为“材料合格性审核”，不代表学校批准立项。正式项目只会在学校结果为通过且整个转项目事务成功时出现。

## 主要实现

### 账号与权限

- `POST /api/auth/register` 创建 student + applicant，bcrypt cost 12，默认每 IP 每小时 8 次。
- 学号和账号唯一，冲突返回统一错误；不记录密码或完整注册请求。
- applicant 只能访问自己的申请、材料、审计和结果。
- 旧 `projects`、`submissions` 列表/下载已显式限定 admin/project_owner，避免新增角色被旧代码误当管理员。
- 学校通过转项目时升级为 project_owner 并递增 `token_version`，旧 applicant 会话立即失效。

### 数据与状态机

- 新迁移：`database/migrations/011_application_approval_loop.sql`；顺序固定为对话 14 的 `009_import_batches_and_reverts.sql`、`010_expand_dynamic_import_modules.sql` 之后。
- 新表覆盖批次、材料要求、申请、不可变文件版本、版本审核、报送记录、学校结果、项目来源和不可变审计事件。
- `project_applications` 生成列唯一索引保证一人同时只有一份进行中申请。
- `project_participations` 生成列唯一索引保证一项目最多一名 owner、一学生最多负责一个未删除项目；服务层进一步保证 `active/checking/completed/archived/stopped` 必须恰好一名学生负责人，`draft` 可以暂时没有负责人。
- 管理员新增/状态转换、标准工作簿、简化导入/回滚、历史首次名单和学校结果转项目都在事务最终提交前调用同一负责人完整性校验；批量关系任一不满足即整批回滚。
- 非法状态跳转由 `applicationWorkflow.js` 统一拒绝。
- 文件版本和审计事件由数据库触发器禁止 UPDATE/DELETE。

### 文件、报送和结果

- 每次上传新增文件版本，保存原文件名、大小、MIME、SHA-256、上传人、时间、提交版本和文件版本。
- 同时校验系统扩展名、材料扩展名、系统单文件大小、材料大小、申请累计容量和受控真实路径。
- 合格申请导出时原子冻结，生成学校 Excel 和材料 ZIP；Excel 用户文本做公式注入转义，ZIP 路径做清理。
- 导出生成失败时自动把本次仍为 `frozen` 的申请恢复为 `eligible`、批次恢复为 `closed`、报送记录标记失败、删除半成品并写不可变审计事件。
- 撤回已报送批次必须填写原因并写审计事件。
- 学校 `.xlsx` 先预检查并计算 SHA-256，再提交事务；合法预检查文件和逐条录入凭据持久保留，预检查不合法的临时原文件在保存错误摘要、文件名、大小和 SHA-256 后立即删除。
- 学校通过：创建或关联项目、唯一 owner、来源记录、申请转项目和账号升级在同一事务中完成。
- 学校未通过：只保留申请与反馈，不创建项目。
- 历史首次正式名单可创建或关联项目；不存在的历史材料只记录 `missing_historical`。

### 页面

- `/register`：申请人自主注册。
- `/applicant/applications`：开放批次、动态申请表、材料上传、重交、版本记录、撤回和结果。
- `/admin/applications`：批次统计、材料合格性审核、冻结报送、Excel/材料包、学校结果预检查和历史名单。

## 迁移说明

先备份目标 MySQL，再执行：

```powershell
cd D:\kexiexitong\server
npm.cmd run db:init
```

初始化器按 `schema_migrations` 只执行未应用的迁移。迁移顺序为 `001` 至 `008`、对话 14 的 `009`、`010`，最后执行本任务 `011`。在执行 011 前，初始化器会自动预查并列出“一项目多负责人、同一负责人重复、正式项目无负责人”三类样例；任一存在即中止，必须人工核实和修复，系统不会伪造负责人。

建议迁移前预查：

```sql
SELECT project_id, COUNT(*) FROM project_participations
WHERE role='owner' AND deleted_at IS NULL GROUP BY project_id HAVING COUNT(*) > 1;

SELECT person_id, COUNT(*) FROM project_participations
WHERE role='owner' AND deleted_at IS NULL GROUP BY person_id HAVING COUNT(*) > 1;

SELECT p.id, p.project_code, p.status
FROM projects p
LEFT JOIN project_participations pp
  ON pp.project_id=p.id AND pp.role='owner' AND pp.deleted_at IS NULL
WHERE p.deleted_at IS NULL AND p.status IN ('active','checking','completed','archived','stopped')
GROUP BY p.id HAVING COUNT(pp.id)=0;
```

新增环境变量均有默认值：

- `REGISTRATION_RATE_LIMIT_WINDOW_MINUTES=60`
- `REGISTRATION_RATE_LIMIT_MAX=8`
- `MAX_APPLICATION_TOTAL_MB=200`
