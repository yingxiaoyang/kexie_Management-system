# 导入模板与数据整理规范

## 一、当前采用的导入方法

对话 14 后，管理员后台新增独立“数据导入”页面。页面统一采用“选择模块、确认定位列、勾选修改字段、下载模板、预检查、确认导入”的流程，当前提供六个模块：

1. `新建项目`：单工作表，一行代表一个项目。
2. `项目基本信息`：按项目编号定位，管理员选择需要修改的项目字段。
3. `人员信息`：按人员类型和人员编号定位，学生编号为学号，教师编号为工号。
4. `项目人员关系`：按项目编号、人员编号和项目身份定位一条关系。
5. `检查记录`：按项目编号和检查阶段定位一条检查记录。
6. `报销记录`：当前每个项目只有一条报销记录，按项目编号定位。

旧的标准工作簿继续兼容，仍可从项目管理页下载和导入，但不再作为新数据导入页的默认方式。

所有正式写入都必须先预检查。预检查会展示新增、修改、移除、跳过、错误和冲突统计，并保存原始文件、文件校验值、管理员、时间、错误清单和逐字段差异。确认导入后才使用数据库事务写入；任一关键步骤失败会整批回滚。

空单元格规则：

- `新建项目导入`：必填字段不能为空，可选字段留空表示保存为空。
- 所有更新模块：空单元格表示“不修改该字段”。
- 只有明确填写 `[清空]`，才把原值清空为数据库空值。
- 项目人员关系导入中，空 `操作` 表示新增或更新；填写 `删除`、`移除`、`remove` 或 `delete` 表示移除该参与关系。

## 二、模块定位规则

| 页面模块 | 固定定位列 | 可选择的修改字段 |
| --- | --- | --- |
| 新建项目 | 无单独定位列，模板包含完整项目字段 | 不适用 |
| 项目基本信息 | 项目编号 | 年度、组别、作品名称、项目类别、立项时间、立项类型、项目状态、备注 |
| 人员信息 | 人员类型、人员编号 | 姓名、学院、单位、电话、QQ、邮箱、职务或职称、账号状态、备注 |
| 项目人员关系 | 项目编号、人员类型、人员编号、项目身份、操作 | 是否主要负责人、加入日期、备注 |
| 检查记录 | 项目编号、检查阶段 | 研究日志数量、评级、检查日期、备注 |
| 报销记录 | 项目编号 | 报销额度、中期申报金额、中期实际金额、阶段申报金额、阶段实际金额、剩余额度、备注 |

项目业务模板第一列固定为“项目编号”。人员信息是全局人员资料，不属于某一个项目，因此使用“人员类型 + 人员编号”定位。

## 三、动态模板字段

### 新建项目导入

工作表第一列固定为“项目编号”，其余项目字段随后排列：

| 字段 | 含义 | 要求 |
| --- | --- | --- |
| `project_code` | 项目编号 | 必填且唯一，按文本保存 |
| `project_year` | 项目所属年度 | 必填，四位年份 |
| `project_group` | 组别 | 可空 |
| `title` | 作品或项目名称 | 必填 |
| `category` | 项目类别 | 可空 |
| `approval_date` | 立项日期 | `YYYY-MM-DD` |
| `approval_type` | 立项类型 | `first` / `supplement`，空值默认 `first` |
| `status` | 项目状态 | `draft` / `active` / `checking` / `completed` / `archived` / `stopped`，空值默认 `active` |
| `remark` | 备注 | 可空 |

已存在且未删除的项目编号会在预检查中标记为跳过；已经软删除的同编号项目可在正式导入时恢复。

### 项目基本信息

模板由管理员选择字段后动态生成。第一列固定为：

```text
项目编号
```

后续可选字段：

```text
项目所属年度、组别、作品名称、项目类别、立项时间、立项类型、项目状态、备注
```

规则：

- 项目编号必须对应现有项目。
- 空单元格表示该字段不修改。
- `[清空]` 表示清空该字段；枚举和必填字段不建议清空。
- 预检查会逐字段展示原值到新值。

### 人员信息

固定定位列为“人员类型、人员编号”。人员类型可填写“学生”或“教师”；人员编号中学生填写学号，教师填写工号。新增人员时必须选择并填写姓名；更新现有人员时，只修改模板中实际填写的字段。

### 项目人员关系

工作表第一行字段：

| 字段 | 含义 | 要求 |
| --- | --- | --- |
| 项目编号 | 固定定位列 | 必须已存在 |
| 人员类型 | 固定定位列 | 学生 / 教师 |
| 人员编号 | 固定定位列 | 学生填学号，教师填工号 |
| 项目身份 | 固定定位列 | 负责人 / 成员 / 指导老师 |
| 操作 | 固定操作列 | 空值表示新增/更新；删除或移除表示移除 |
| 是否主要负责人 | 可选修改字段 | 是 / 否 |
| 加入日期 | 可选修改字段 | `YYYY-MM-DD`，未知可空 |
| 备注 | 可选修改字段 | 可空 |

同一项目、同一人员、同一身份不能在同一份文件中重复。负责人和成员导入会检查当前参与规则；第一版用于历史初始化或管理员批量纠错，不替代后续人员变更审批。

### 检查记录

固定定位列为“项目编号、检查阶段”，检查阶段可填写“中期检查”或“阶段检查”。其余检查字段由管理员勾选；不存在的项目阶段记录会新增，已存在的记录只修改非空字段。

### 报销记录

固定定位列为“项目编号”。当前数据库约束为每个项目一条报销记录；不存在时新增，已存在时只修改管理员选择且单元格非空的字段。

## 四、导入记录与回滚

正式导入后，系统永久保存：

- 批次编号、导入类型、模式、状态。
- 原始文件、文件 SHA-256 校验值和文件大小。
- 操作管理员、预检查时间、确认时间和回滚时间。
- 每一行的新增、修改、移除、跳过、错误或冲突状态。
- 每个字段的修改前值和修改后值。

管理员可以在“数据导入”页面查看记录详情、下载原始文件、下载错误清单、导出差异。

回滚采用追加记录方式，类似 Git `revert`：

- 不删除原导入历史。
- 只有当前值仍等于该批次导入后值时才自动恢复。
- 被后续操作修改的内容标记为冲突并跳过。
- 第一版支持项目、人员、项目人员关系、检查记录和报销记录的整批安全回滚，不提供强制覆盖冲突。

## 五、标准工作簿兼容方式

历史 Excel 不需要保持原来的排版，也不要求原表直接导入。处理时统一把数据整理到标准工作簿：

```text
D:\kexiexitong\server\templates\import\科研项目数据标准导入模板.xlsx
```

工作簿包含 5 张数据表：

1. `1_项目`：一个项目一行。
2. `2_人员`：一个学生或老师一行，同一个人只出现一次。
3. `3_参与关系`：一个人参与一个项目的一种身份占一行。
4. `4_检查记录`：一个项目的一次检查占一行。
5. `5_报销记录`：一个项目占一行。

工作簿中另有 `导入说明` 和 `字段字典`，仅供查看，不作为业务数据导入。

这种方式不依赖原始 Excel 的合并单元格、横向人员列、标题行或统计行。只要文档中已确认的字段都整理进标准表，后续导入不会因为原表版式不同而增加数据库字段。

## 六、整理旧表时必须遵守的规则

- 第 1 行必须保留模板原有字段名，不要改名、删除或调整含义。
- 从第 2 行开始填写数据，每一行只表示一条记录。
- 不使用合并单元格、多层表头、标题行、空白分隔行、小计行或合计行。
- 不通过颜色、字体、批注表达业务含义，需要保留的内容写进对应字段或 `remark`。
- 不在单元格内放多个人名、多个学号或多个项目编号，必须拆成多行。
- 学号、工号、项目编号、电话、QQ 按文本保存，防止前导零丢失或变成科学计数法。
- 日期统一使用 `YYYY-MM-DD`，例如 `2026-08-05`。
- 金额只填写数字，不带人民币符号、千分位逗号或“元”，最多两位小数，例如 `3000.00`。
- 空值直接留空，不填写 `/`、`-`、`无`、`暂无`、`不详` 等占位文本。
- 枚举字段必须使用模板下拉列表中的代码值，不自行创造近义词。
- 不使用公式。若原表中有公式，整理后粘贴公式计算出的值。
- 正式导入前删除测试数据和说明性示例，只保留真实数据。

## 七、各数据表应整理成什么样子

### 1_项目

一个项目只出现一次，以 `project_code` 作为唯一识别编号。

| 字段 | 含义 | 要求 |
| --- | --- | --- |
| `project_year` | 项目所属年度 | 必填，四位年份 |
| `project_group` | 组别 | 可空 |
| `project_code` | 项目编号 | 必填且唯一，按文本保存 |
| `title` | 作品或项目名称 | 必填 |
| `category` | 项目类别 | 可空 |
| `approval_date` | 立项日期 | `YYYY-MM-DD` |
| `approval_type` | 立项类型 | `first` / `supplement` |
| `status` | 项目状态 | `draft` / `active` / `checking` / `completed` / `archived` / `stopped` |
| `remark` | 备注 | 可空 |

### 2_人员

学生用学号识别，老师用工号识别。同一个人无论参与几个项目，都只在人员表中保留一行。

| 字段 | 含义 | 要求 |
| --- | --- | --- |
| `person_type` | 人员类型 | `student` / `teacher` |
| `name` | 姓名 | 必填 |
| `student_no` | 学号 | 学生必填且唯一，老师留空 |
| `teacher_no` | 工号 | 老师必填且唯一，学生留空 |
| `college` | 学院 | 可空 |
| `unit` | 单位 | 可空 |
| `phone` | 电话 | 按文本保存 |
| `qq` | QQ | 按文本保存 |
| `email` | 邮箱 | 可空 |
| `title` | 职务或职称 | 可空 |
| `account_status` | 账号状态 | `none` / `enabled` / `disabled`，导入人员时通常填 `none` |
| `remark` | 备注 | 可空 |

人员导入不会直接生成登录密码。第一版仍由管理员在账号管理中为项目负责人创建或重置账号。

### 3_参与关系

原表中“负责人、成员、指导老师”无论是横向多列还是挤在一个单元格，都必须拆成多行。

例如某项目有 1 名负责人、2 名成员、1 名指导老师，应整理成 4 行参与关系。

| 字段 | 含义 | 要求 |
| --- | --- | --- |
| `project_code` | 项目编号 | 必须已存在于 `1_项目` |
| `person_type` | 人员类型 | `student` / `teacher` |
| `person_identifier` | 人员编号 | 学生填学号，老师填工号 |
| `role` | 项目身份 | `owner` / `member` / `advisor` |
| `is_primary_owner` | 是否主要负责人 | 主要负责人填 `1`，其他填 `0` |
| `joined_at` | 加入日期 | `YYYY-MM-DD`，未知可空 |
| `remark` | 备注 | 可空 |

同一项目、同一人员、同一身份不能重复。`owner` 通常对应学生负责人，`member` 对应学生成员，`advisor` 对应指导老师。

### 4_检查记录

中期检查和阶段检查分别占一行。同一项目可以有两行，但同一个检查阶段只能有一行。

| 字段 | 含义 | 要求 |
| --- | --- | --- |
| `project_code` | 项目编号 | 必须已存在于 `1_项目` |
| `check_phase` | 检查阶段 | `midterm` / `stage` |
| `research_log_count` | 研究日志数量 | 非负整数 |
| `rating` | 评级 | 按文档或原始记录填写 |
| `checked_at` | 检查日期 | `YYYY-MM-DD` |
| `remark` | 备注 | 可空 |

### 5_报销记录

一个项目只保留一行报销汇总。原表如果按多笔流水记录，需要先按项目汇总成下面的字段。

| 字段 | 含义 | 要求 |
| --- | --- | --- |
| `project_code` | 项目编号 | 必须已存在于 `1_项目` |
| `budget_amount` | 报销额度 | 数字，最多两位小数 |
| `midterm_claim_amount` | 中期申报金额 | 数字，最多两位小数 |
| `midterm_actual_amount` | 中期实际金额 | 数字，最多两位小数 |
| `stage_claim_amount` | 阶段申报金额 | 数字，最多两位小数 |
| `stage_actual_amount` | 阶段实际金额 | 数字，最多两位小数 |
| `remaining_amount` | 剩余额度 | 数字，最多两位小数 |
| `remark` | 备注 | 可空 |

`remaining_amount` 以文档中的最终确认值为准。若需要由系统自动计算，后续实现导入功能时再统一增加计算和校验规则。

## 八、材料文件和归档记录如何处理

材料文件不放进 Excel。项目负责人在材料任务中直接上传 PDF、Word、Excel、图片或压缩包，系统保存文件和提交记录。

归档记录也不需要人工整理成导入表。管理员在系统中执行归档导出后，由系统自动记录导出人、模板、范围、文件路径、状态和时间。

因此，历史表格整理只需要处理项目、人员、参与关系、检查和报销 5 类结构化数据。

## 九、推荐的导入顺序

1. 导入项目。
2. 导入人员。
3. 导入项目参与关系。
4. 导入检查记录。
5. 导入报销记录。

项目和人员是基础数据，参与关系、检查和报销都通过项目编号或人员编号关联，不能提前导入。

## 十、正式导入流程

第一版导入功能按以下流程实现：

1. 管理员上传标准工作簿。
2. 系统只做预检查，不立即写入数据库。
3. 系统返回各表总行数、可导入行数和错误行数。
4. 有错误时下载错误清单，按“工作表 + Excel 行号 + 字段 + 原因”修改原文件。
5. 全部通过后，管理员确认正式导入。
6. 正式导入使用数据库事务；任一关键步骤失败时整批回滚，避免导入一半。

默认使用“仅新增”模式，遇到数据库中已存在的唯一编号时报错，不静默覆盖。需要修正已有数据时，明确选择“更新已有数据”模式。

## 十一、唯一识别和重复判断规则

| 数据类型 | 唯一识别规则 |
| --- | --- |
| 项目 | `project_code` |
| 学生 | `student_no` |
| 老师 | `teacher_no` |
| 参与关系 | `project_code + person_type + person_identifier + role` |
| 检查记录 | `project_code + check_phase` |
| 报销记录 | `project_code` |

同一份工作簿内出现重复唯一键时，预检查直接报错，不合并、不覆盖。

## 十二、兼容的文件形式

推荐直接上传标准 `.xlsx` 工作簿。目录中同时保留 5 个 CSV 模板，便于程序测试或将单张表导出后单独处理：

```text
D:\kexiexitong\server\templates\import
```

CSV 文件统一使用 UTF-8 编码，字段和整理规则与标准工作簿完全一致。
