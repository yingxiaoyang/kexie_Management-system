# 导入模板与数据整理规范

## 一、最终采用的导入方法

历史 Excel 不需要保持原来的排版，也不要求原表直接导入。处理时统一把数据整理到标准工作簿：

```text
D:\kexiexitong\server\templates\import\科研项目数据标准导入模板.xlsx
```

工作簿包含 5 张数据表：

1. `1_项目`：一个项目一行。
2. `2_人员`：一个学生或老师一行，同一个人只出现一次。
3. `3_参与关系`：一个人参与一个项目的一种身份占一行。
4. `4_检查记录`：一个项目的一次检查占一行。
5. `5_报销记录`：一个项目占一行。

工作簿中另有 `导入说明` 和 `字段字典`，仅供查看，不作为业务数据导入。

这种方式不依赖原始 Excel 的合并单元格、横向人员列、标题行或统计行。只要文档中已确认的字段都整理进标准表，后续导入不会因为原表版式不同而增加数据库字段。

## 二、整理旧表时必须遵守的规则

- 第 1 行必须保留模板原有字段名，不要改名、删除或调整含义。
- 从第 2 行开始填写数据，每一行只表示一条记录。
- 不使用合并单元格、多层表头、标题行、空白分隔行、小计行或合计行。
- 不通过颜色、字体、批注表达业务含义，需要保留的内容写进对应字段或 `remark`。
- 不在单元格内放多个人名、多个学号或多个项目编号，必须拆成多行。
- 学号、工号、项目编号、电话、QQ 按文本保存，防止前导零丢失或变成科学计数法。
- 日期统一使用 `YYYY-MM-DD`，例如 `2026-08-05`。
- 金额只填写数字，不带人民币符号、千分位逗号或“元”，最多两位小数，例如 `3000.00`。
- 空值直接留空，不填写 `/`、`-`、`无`、`暂无`、`不详` 等占位文本。
- 枚举字段必须使用模板下拉列表中的代码值，不自行创造近义词。
- 不使用公式。若原表中有公式，整理后粘贴公式计算出的值。
- 正式导入前删除测试数据和说明性示例，只保留真实数据。

## 三、各数据表应整理成什么样子

### 1_项目

一个项目只出现一次，以 `project_code` 作为唯一识别编号。

| 字段 | 含义 | 要求 |
| --- | --- | --- |
| `project_year` | 项目所属年度 | 必填，四位年份 |
| `project_group` | 组别 | 可空 |
| `project_code` | 项目编号 | 必填且唯一，按文本保存 |
| `title` | 作品或项目名称 | 必填 |
| `category` | 项目类别 | 可空 |
| `approval_date` | 立项日期 | `YYYY-MM-DD` |
| `approval_type` | 立项类型 | `first` / `supplement` |
| `status` | 项目状态 | `draft` / `active` / `checking` / `completed` / `archived` / `stopped` |
| `remark` | 备注 | 可空 |

### 2_人员

学生用学号识别，老师用工号识别。同一个人无论参与几个项目，都只在人员表中保留一行。

| 字段 | 含义 | 要求 |
| --- | --- | --- |
| `person_type` | 人员类型 | `student` / `teacher` |
| `name` | 姓名 | 必填 |
| `student_no` | 学号 | 学生必填且唯一，老师留空 |
| `teacher_no` | 工号 | 老师必填且唯一，学生留空 |
| `college` | 学院 | 可空 |
| `unit` | 单位 | 可空 |
| `phone` | 电话 | 按文本保存 |
| `qq` | QQ | 按文本保存 |
| `email` | 邮箱 | 可空 |
| `title` | 职务或职称 | 可空 |
| `account_status` | 账号状态 | `none` / `enabled` / `disabled`，导入人员时通常填 `none` |
| `remark` | 备注 | 可空 |

人员导入不会直接生成登录密码。第一版仍由管理员在账号管理中为项目负责人创建或重置账号。

### 3_参与关系

原表中“负责人、成员、指导老师”无论是横向多列还是挤在一个单元格，都必须拆成多行。

例如某项目有 1 名负责人、2 名成员、1 名指导老师，应整理成 4 行参与关系。

| 字段 | 含义 | 要求 |
| --- | --- | --- |
| `project_code` | 项目编号 | 必须已存在于 `1_项目` |
| `person_type` | 人员类型 | `student` / `teacher` |
| `person_identifier` | 人员编号 | 学生填学号，老师填工号 |
| `role` | 项目身份 | `owner` / `member` / `advisor` |
| `is_primary_owner` | 是否主要负责人 | 主要负责人填 `1`，其他填 `0` |
| `joined_at` | 加入日期 | `YYYY-MM-DD`，未知可空 |
| `remark` | 备注 | 可空 |

同一项目、同一人员、同一身份不能重复。`owner` 通常对应学生负责人，`member` 对应学生成员，`advisor` 对应指导老师。

### 4_检查记录

中期检查和阶段检查分别占一行。同一项目可以有两行，但同一个检查阶段只能有一行。

| 字段 | 含义 | 要求 |
| --- | --- | --- |
| `project_code` | 项目编号 | 必须已存在于 `1_项目` |
| `check_phase` | 检查阶段 | `midterm` / `stage` |
| `research_log_count` | 研究日志数量 | 非负整数 |
| `rating` | 评级 | 按文档或原始记录填写 |
| `checked_at` | 检查日期 | `YYYY-MM-DD` |
| `remark` | 备注 | 可空 |

### 5_报销记录

一个项目只保留一行报销汇总。原表如果按多笔流水记录，需要先按项目汇总成下面的字段。

| 字段 | 含义 | 要求 |
| --- | --- | --- |
| `project_code` | 项目编号 | 必须已存在于 `1_项目` |
| `budget_amount` | 报销额度 | 数字，最多两位小数 |
| `midterm_claim_amount` | 中期申报金额 | 数字，最多两位小数 |
| `midterm_actual_amount` | 中期实际金额 | 数字，最多两位小数 |
| `stage_claim_amount` | 阶段申报金额 | 数字，最多两位小数 |
| `stage_actual_amount` | 阶段实际金额 | 数字，最多两位小数 |
| `remaining_amount` | 剩余额度 | 数字，最多两位小数 |
| `remark` | 备注 | 可空 |

`remaining_amount` 以文档中的最终确认值为准。若需要由系统自动计算，后续实现导入功能时再统一增加计算和校验规则。

## 四、材料文件和归档记录如何处理

材料文件不放进 Excel。项目负责人在材料任务中直接上传 PDF、Word、Excel、图片或压缩包，系统保存文件和提交记录。

归档记录也不需要人工整理成导入表。管理员在系统中执行归档导出后，由系统自动记录导出人、模板、范围、文件路径、状态和时间。

因此，历史表格整理只需要处理项目、人员、参与关系、检查和报销 5 类结构化数据。

## 五、推荐的导入顺序

1. 导入项目。
2. 导入人员。
3. 导入项目参与关系。
4. 导入检查记录。
5. 导入报销记录。

项目和人员是基础数据，参与关系、检查和报销都通过项目编号或人员编号关联，不能提前导入。

## 六、正式导入流程

第一版导入功能按以下流程实现：

1. 管理员上传标准工作簿。
2. 系统只做预检查，不立即写入数据库。
3. 系统返回各表总行数、可导入行数和错误行数。
4. 有错误时下载错误清单，按“工作表 + Excel 行号 + 字段 + 原因”修改原文件。
5. 全部通过后，管理员确认正式导入。
6. 正式导入使用数据库事务；任一关键步骤失败时整批回滚，避免导入一半。

默认使用“仅新增”模式，遇到数据库中已存在的唯一编号时报错，不静默覆盖。需要修正已有数据时，明确选择“更新已有数据”模式。

## 七、唯一识别和重复判断规则

| 数据类型 | 唯一识别规则 |
| --- | --- |
| 项目 | `project_code` |
| 学生 | `student_no` |
| 老师 | `teacher_no` |
| 参与关系 | `project_code + person_type + person_identifier + role` |
| 检查记录 | `project_code + check_phase` |
| 报销记录 | `project_code` |

同一份工作簿内出现重复唯一键时，预检查直接报错，不合并、不覆盖。

## 八、兼容的文件形式

推荐直接上传标准 `.xlsx` 工作簿。目录中同时保留 5 个 CSV 模板，便于程序测试或将单张表导出后单独处理：

```text
D:\kexiexitong\server\templates\import
```

CSV 文件统一使用 UTF-8 编码，字段和整理规则与标准工作簿完全一致。
