# 科研项目管理平台系统字段字典

更新日期：2026-08-19

适用项目：`D:\kexiexitong`

## 1. 文档用途

本文件是各任务统一确认系统字段的入口，覆盖：

1. MySQL 数据库中的全部物理字段。
2. Excel 简化导入和标准工作簿使用的业务字段。
3. 项目数据报表设计器提供的字段。
4. 归档模板可以使用的命名占位字段。
5. 只在页面或导出时计算、不直接存入数据库的派生字段。
6. 已提出但尚未开发的字段，避免其他任务误认为已经存在。

字段真实性优先级为：最新数据库迁移文件、实际数据库结构、本字段字典、其他需求和交接文档。新增、删除、改名或改变字段含义时，必须同时更新数据库迁移、相关代码和本文件，不能只改其中一处。

截至迁移 `011_application_approval_loop.sql`（通过临时 MySQL 实际执行核对）：

- 数据库共 31 张表、362 个物理字段。
- 扣除内部迁移表 `schema_migrations` 后，共 30 张业务表、360 个业务物理字段。
- 报表设计器提供 38 个字段键。
- 归档模板提供 25 个命名占位字段。
- 报表字段和归档占位字段大多来源于数据库或计算结果，不能与 360 个业务物理字段直接相加。

## 2. 标记说明

| 标记 | 含义 |
| --- | --- |
| 人工 | 管理员或负责人可以通过业务页面、导入或审核操作填写 |
| 系统 | 系统自动生成或维护，业务导入不得直接覆盖 |
| 关联 | 保存另一张表的主键 ID |
| 派生 | 查询或导出时计算，不直接存入该业务字段 |
| 软删 | `deleted_at` 有值表示逻辑删除，历史记录仍保留 |

老师基础资料和参与项目已经分别存在 `people` 与 `project_participations`。尚未正式加入报表和归档字段的内容包括：

- 指导项目数量。
- 当前进行中指导项目数量。
- 指导项目编号或名称列表。
- 老师指导项目详情的报表重复区域字段。

这些内容原则上优先作为查询派生字段，不应在 `people` 中重复保存容易过期的统计数量。

## 15. 字段变更规则

今后任何任务涉及字段时必须执行：

1. 开始开发前先阅读本文件和最新迁移。
2. 新增数据库字段必须创建新的迁移文件，不能修改已经执行的旧迁移。
3. 同步更新本文件中的表字段、枚举、JSON 结构、导入字段、报表字段或归档占位字段。
4. 若字段只用于计算，标记为“派生”，不要为了导出方便就重复存入数据库。
5. 若字段尚在讨论，写入“尚未开发”部分，不得提前出现在正式接口和模板中。
6. 每个任务交接记录必须写明“新增、修改、删除了哪些字段”。
7. 字段改名必须提供兼容或迁移方案，不能只改页面中文名称。

数据库字段的最终核对命令应查询 `information_schema.COLUMNS`；报表字段核对 `REPORT_FIELD_GROUPS`；归档字段核对 `ARCHIVE_PLACEHOLDERS`；导入字段核对 `server\src\routes\imports.js`。

## 立项申请 `project_applications`

| 字段 | 类型/取值 | 含义与约束 |
| --- | --- | --- |
| `application_batch_id` | 批次外键 | 一人同一批次只能有一条申请 |
| `applicant_user_id` / `applicant_person_id` | 账号/人员外键 | 申请归属；applicant 接口必须同时匹配当前账号 |
| `status` | 见状态机 | 不允许任意更新，接口必须校验合法跳转 |
| `application_data` | JSON | 按批次字段 schema 校验，拒绝未知字段 |
| `submission_version` | 正整数 | 每次正式提交递增；草稿上传写入下一个版本 |
| `internal_review_*` | 审核人、时间、原因 | 仅表示材料合格性，不表示学校批准 |
| `frozen_at` | 时间 | 纳入报送批次后冻结 |
| `school_result_*` | 时间、备注 | 学校正式反馈 |
| `project_id` | 正式项目外键 | 仅学校通过且事务转项目成功后填写 |
| `active_applicant_person_id` | 生成列 | 对进行中状态生成学生 ID并加唯一索引，保证同一时间一份申请 |

申请状态机：

```text
draft ─提交→ submitted ─材料合格→ eligible ─报送冻结→ frozen
  │                    └材料退回→ returned ─重新提交→ submitted
  └撤回→ withdrawn                 └撤回→ withdrawn

frozen ─学校通过→ school_approved ─同事务转项目→ converted
       ├学校未通过→ school_rejected
       └管理员写明原因撤回报送→ eligible
```

`draft`、`submitted`、`returned`、`eligible`、`frozen`、`school_approved` 属于进行中状态。`school_rejected`、`withdrawn`、`converted` 释放“进行中申请”唯一槽位。

## 正式项目负责人约束

`project_participations` 新增两个生成列和唯一索引：

- `active_owner_project_id`：同一未删除项目最多一名 owner；正式状态还由服务端提交前校验必须恰好一名。
- `active_owner_person_id`：同一学生最多负责一个未删除正式项目。

学校通过转项目事务必须依次锁定申请、检查负责人约束、创建或关联项目、建立 owner 关系、写来源、更新申请、升级账号并写审计事件；任一步失败整批回滚。
